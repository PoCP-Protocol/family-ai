## 1. 读法：从 PPT 表述到 Family 可裁决能力

PPT 中的“功能”不是可直接开发的需求。每项功能必须先被拆为家庭用户任务、平台候选能力、最小数据、授权与风险边界，再由独立 App Gate 判断是否允许进入任务契约。本拆解采用如下固定八项格式：

| 字段 | 说明 |
|---|---|
| 1. PPT 原始功能/页面线索 | 可回溯到原始 PPT 页码的业务或页面表述。 |
| 2. Family 可迁移能力候选 | 只描述未来可裁决的能力意图，不等于已授权实现。 |
| 3. Consent / 隐私 / 数据边界 | 家庭所有权、最小化、用途限定、撤回与可见性要求。 |
| 4. 风险路由与 Human Gate | 哪些情形应停止、扣留、转人工或申请新 Gate。 |
| 5. 文本等价路径 | 无图像、无语音、无外部模型时必须完整可用的路径。 |
| 6. fail-closed 条件 | 缺少任何关键资格时必须拒绝、空显示或不执行。 |
| 7. 明确不得证明的事项 | 不能从 E1 材料或 App 过程推导的结论。 |
| 8. 独立 App Gate 裁决问题 | 若进入实现，必须得到的明确授权。 |

## 2. 功能域 A：问题入口与家庭当下支持

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 商业模式材料提出“孩子问题是入口”，并在用户路径中以“孩子出现现实问题—内容、沙龙、家庭测评”作为触发；战略白皮书列出亲子沟通、学习习惯、手机管理、自驱力不足等高频痛点。[1] |
| **2. Family 可迁移能力候选** | 家庭私有的“说说现在的需要”入口：监护人以文本描述当下情境，确认服务意图，随后只看见已准入候选或明确的暂不行动。候选纵切是“亲子沟通紧张时的当下支持”，仍仅为裁决输入。 |
| **3. Consent / 隐私 / 数据边界** | Need/Intent 只归属当前服务端解析的 `family_id` 与 child subject；只为当前服务链使用；最小化显示；SERVICE consent、年龄与受信任家庭上下文是前置；撤回后不得复用历史上下文。 |
| **4. 风险路由与 Human Gate** | HIGH_RISK/REVIEW 只能进入已存在的扣留/handoff 状态；不得由 UI 给出被扣留响应。若需要诊断、危机评估、真人咨询或跨家庭转介，停止并申请独立 Gate。 |
| **5. 文本等价路径** | 一个文本输入、可选结构化意图、明确确认、文本资源卡、文本“暂不行动”按钮；不依赖语音、图片、量表、聊天模型或图形报告。 |
| **6. fail-closed 条件** | 无会话、disabled account、无 ACTIVE binding/membership、ambiguous context、无 SERVICE consent、跨家庭 child、年龄不匹配或风险闸不通过时：拒绝写入且不显示候选。 |
| **7. 明确不得证明的事项** | 不证明孩子存在问题、问题原因、风险等级、教育诊断、干预效果、孩子/父母画像或家庭改变。 |
| **8. 独立 App Gate 裁决问题** | 是否允许一个仅消费既有 Need/Intent API 的移动优先文本入口？是否允许使用“亲子沟通紧张”作为合成场景文案而不将其写成任何标签？ |

## 3. 功能域 B：理解、测评与成长报告

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 商业模式材料提出家庭测评、AI 诊断、父母成长报告；战略白皮书提出成长测评、报告、画像完整度和成长档案。[1] [2] |
| **2. Family 可迁移能力候选** | 当前仅可研究“家庭自行填写的、可撤回的服务意图确认”与“家庭私有服务过程摘要”。正式测评、报告、画像或诊断不是本 App Gate 的实现目标。 |
| **3. Consent / 隐私 / 数据边界** | 任何未来测评必须按目的拆分 consent，明确输入来源、题目版权、儿童/第三方信息、保留期、结果可见性、删除请求及是否写入核心对象。不得把自由文本或量表结果直接写入成长 ontology。 |
| **4. 风险路由与 Human Gate** | 涉及心理健康、危机、诊断、未成年人敏感信息、第三方叙述或自动建议时，需要独立专家/治理审阅；有外部模型即需 Model Gateway 与独立授权。 |
| **5. 文本等价路径** | 若未来获准，仅可用清晰文本问题、跳过/退出、人工可读说明和无结论状态；不能要求上传照片、语音或视频。 |
| **6. fail-closed 条件** | 未定义目的/consent/保留期/人工复核/证据来源时，不收集、不生成报告、不形成画像、不推荐资源。 |
| **7. 明确不得证明的事项** | 测评分数、报告或自家材料不证明儿童能力、家长风格、家庭关系真实状态、改变效果或长期预测。 |
| **8. 独立 App Gate 裁决问题** | 是否单独授权“非诊断、家庭自填、可撤回的服务偏好问卷”设计？是否允许任何报告，还是先只显示事实型服务过程摘要？ |

## 4. 功能域 C：每日行动、挑战与计划

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 商业模式材料提出 21 天挑战、每日任务、90 天计划；战略白皮书提出任务、打卡、反馈、陪练与标准化交付。[1] [2] |
| **2. Family 可迁移能力候选** | 对已经由家庭明确选择的资源，以声明性 Plan/ServiceCase 显示“下一步、状态、可暂停”而非自动化任务系统。后续可研究低压力、家庭可调整的行动节奏。 |
| **3. Consent / 隐私 / 数据边界** | 计划和 Case 只在 Family Decision 后创建；仅保存必要服务过程事实与家庭主观回访；不得默认记录行为、位置、设备、连续打卡或未成年人日常生活数据。 |
| **4. 风险路由与 Human Gate** | T2 不通过、consent 撤回、资源降级、PRACTICE 无 executor 或需要真实人工交付时，停止执行；若要开通提醒、通知或真人陪练，分别申请 Gate。 |
| **5. 文本等价路径** | 简短文本计划、状态描述、暂停和退出；不以动画、排行榜、连续天数、勋章或行为设计制造压力。 |
| **6. fail-closed 条件** | NO_ACTION 不创建 Plan/Case；资源未准入或 T2 不通过不创建 Case；同键重试不重复创建；PRACTICE 无 executor 不可选。 |
| **7. 明确不得证明的事项** | 打卡、任务完成、服务进度或主观帮助感不证明行为改变、学习效果、关系改善或家庭成长结果。 |
| **8. 独立 App Gate 裁决问题** | 第一阶段是否只显示既有 Plan/Case 的声明性状态，而不引入任务、打卡、通知、激励或长期挑战？ |

## 5. 功能域 D：资源、课程与内容资产

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 两份材料都把成熟课程、训练营、内容矩阵、课件、任务与知识库视为平台资产；商业模式材料强调“不是再造一套课程”，而是将成熟内容纳入长期陪伴。[1] [2] |
| **2. Family 可迁移能力候选** | 将已登记、已准入的 CONTENT / PRACTICE 资源作为家庭 Decision 的候选输入；在家长可读卡片上展示来源、适用阶段、风险、版权和 admission 状态。 |
| **3. Consent / 隐私 / 数据边界** | 资源选择不得依赖跨家庭画像或隐藏推断；只在当前家庭服务意图内匹配；资源自身须继承 provenance、version、evidence、risk、copyright、admission。 |
| **4. 风险路由与 Human Gate** | E1 材料只能支持来源/版权与内容资产事实；效果声称、版权不清、风险降级、第三方内容、未成年人敏感主题或使用外部模型生成内容时，进入独立 Evidence/Human/Model Gate。 |
| **5. 文本等价路径** | 每个候选须有文本标题、用途、来源、限制、风险说明和“暂不选择”路径；不要求观看视频、扫描图片或接入聊天。 |
| **6. fail-closed 条件** | 未准入、降级、版权不明、风险未处理、E1 被描述为效果证据、无 real Practice executor：不显示、不可选、不可执行。 |
| **7. 明确不得证明的事项** | 课程存在、内容已准入或家庭选择，不证明课程有效、适龄结论正确、孩子会改变或资源已实际交付。 |
| **8. 独立 App Gate 裁决问题** | App 是否只显示已准入 CONTENT，且将 PRACTICE 维持在无 executor 时不可见？家长可读 evidence/provenance 字段应展示哪些最小摘要？ |

## 6. 功能域 E：家庭服务过程、档案与私有进度

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 商业模式材料提出服务进度、计划阶段、陪跑角色、服务档案、咨询活动与客户后台；战略白皮书强调可记录数据、标准化交付、反馈和质量管理。[1] [2] |
| **2. Family 可迁移能力候选** | 家庭私有的服务过程视图：当前 Need/Intent、已作决定、Plan/Case 状态、主观帮助感、人工交接等待和 consent 状态。 |
| **3. Consent / 隐私 / 数据边界** | 按 family scope 显示；Context Reuse 要求有效 SERVICE consent；撤回后默认空投影但保留最小事实审计；不显示内部 ID、他人信息、隐藏运营标签或第三方笔记。 |
| **4. 风险路由与 Human Gate** | REVIEW/HIGH_RISK 只呈现等待/安全状态，不呈现扣留响应；若要展示顾问身份、预约、服务记录、工单分派或组织协作，需独立 Gate。 |
| **5. 文本等价路径** | 文本时间线、状态、下一步、暂停/返回、可选主观回访；无需图表、照片、音频、排名或成就徽章。 |
| **6. fail-closed 条件** | consent 撤回、家庭范围不符、历史对象不属同一 Case/Family、内部状态无法解释时：空投影或拒绝，绝不降级展示。 |
| **7. 明确不得证明的事项** | 服务档案、进度条、Case 关闭或主观反馈不证明成长效果、顾问交付质量、课程结果或画像准确性。 |
| **8. 独立 App Gate 裁决问题** | 是否允许第一阶段只显示已存在的家庭私有过程事实？哪些字段是家庭可读最小集合，哪些永远不得进入家庭 UI？ |

## 7. 功能域 F：人工协同、顾问与线下信任

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 商业模式材料提出名师咨询、预约沟通、线下沙龙、城市活动、顾问与班主任；战略白皮书提出助教 SOP、交付负责人、AI 助手与成长规划师。[1] [2] |
| **2. Family 可迁移能力候选** | 仅可呈现安全的“已转人工/等待确认”状态，以及家庭仍可暂停/返回的选择；复用已有 REVIEW/HIGH_RISK handoff traceability。 |
| **3. Consent / 隐私 / 数据边界** | 当前不得把家庭数据发送给真人、组织或第三方；未来任何 handoff 必须明确接收方、目的、最小字段、有效期、撤销、查看审计和审批。 |
| **4. 风险路由与 Human Gate** | 高风险先扣留，开放 handoff；真人服务、预约、排班、专家资料、城市/机构协作都要求独立 Human/Organization/AccessGrant Gate。 |
| **5. 文本等价路径** | 文本说明“系统正在保护此请求；当前没有自动回复；你可暂停或寻求当地紧急帮助”；不依赖电话、视频或实时聊天。 |
| **6. fail-closed 条件** | 未有接收方授权、AccessGrant、目的限定、最小字段规则或人工接单证据时，不转发、不承诺联系、不创建预约。 |
| **7. 明确不得证明的事项** | handoff 记录不证明人工已服务、专家资质、服务有效、线下活动安全或顾问建议正确。 |
| **8. 独立 App Gate 裁决问题** | 是否允许第一阶段只显示 handoff 的安全状态而不开放真人服务？如何设计不造成“已有人响应”误解的文案？ |

| **7. 明确不得证明的事项** | 家庭故事、主观反馈、案例和邀请不证明教育效果、榜样性、家庭画像、同伴适配或平台治理正确。 |
| **8. 独立 App Gate 裁决问题** | 如未来探索分享，是否先限定为家庭自持导出草稿而非公开？是否完全避免儿童/家庭成长内容的社会传播？ |

| **7. 明确不得证明的事项** | 订阅、续费、付费、活动参加或 LTV 指标不证明成长结果、服务质量或家庭需求。 |
| **8. 独立 App Gate 裁决问题** | 商业化是否永久与家庭支持体验分离？若未来开通，是否先限定为只读权益说明而非交易？ |

## 10. 功能域 I：AI、Agent、数据资产与经营看板

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 战略白皮书提出知识库、用户画像、成长规划、陪练执行、督导反馈、数据中台，以及家长顾问、孩子陪练、助教助手、成长规划师和经营助手等 Agent。[2] |
| **2. Family 可迁移能力候选** | 当前仅可复用已收口的 Principal 安全管线、REVIEW/HIGH_RISK handoff 和确定性服务编排。任何 AI 助手或 Agent 都不是当前 App Gate 的实现范围。 |
| **3. Consent / 隐私 / 数据边界** | 未来 AI 使用必须按独立目的、输入类别、处理者、模型、保留、输出用途和撤回声明 consent；模型输入不得越过家庭范围或进入跨家庭学习。 |
| **4. 风险路由与 Human Gate** | 外部模型、训练、自学习、推荐、画像、预警和经营分析须独立 Model Gateway / Evidence / Human Gate；高风险只可扣留/转人工。 |
| **5. 文本等价路径** | 无模型时仍可完成家庭表达、资源候选、家庭决定、私有进度和回访；不得因未启用 AI 而失去基本服务。 |
| **6. fail-closed 条件** | 未授权模型、无处理 consent、无风险路由、无 evidence 或试图写入核心 ontology 时：不调用、不写入、不推荐、不展示自动结论。 |
| **7. 明确不得证明的事项** | “AI 越用越懂”“画像完整度”“数据壁垒”不证明模型正确、建议有效、家庭特征真实或治理可放行。 |
| **8. 独立 App Gate 裁决问题** | 第一条 App 纵切是否明确零外部模型、零训练、零 AI 自由文本生成？若未来加入受控模型，最小输入和人工复核如何定义？ |

## 11. 功能域 J：品牌、信息架构与移动体验调性

| 拆解项 | 内容 |
|---|---|
| **1. PPT 原始功能/页面线索** | 商业模式材料使用深蓝信任底色、浅蓝主体、阶段旅程、账户后台卡片和少量暖色强调；战略白皮书使用深色结论页、留白、分阶段路线与清晰表格。[1] [2] |
| **2. Family 可迁移能力候选** | App-first 的视觉语法：温暖、克制、可信、可解释；单一当下任务；大留白；低刺激状态；清晰返回/暂停；在安全确认和风险状态使用深色强调。 |
| **3. Consent / 隐私 / 数据边界** | 界面不得通过默认勾选、暗黑模式诱导、模糊同意文案或社会比较要求数据授权；敏感状态必须最小展示。 |
| **4. 风险路由与 Human Gate** | 涉及风险提示、人工等待、撤回、删除请求、同意变更、未成年人信息时，文案与交互必须经单独安全/内容审阅。 |
| **5. 文本等价路径** | 所有卡片、状态、资源、图表、颜色提示都有清晰文本；颜色不作为唯一信息渠道；屏幕阅读器和低带宽路径完整。 |
| **6. fail-closed 条件** | 不能解释的状态、缺失的资源限制、无来源的效果文案、无 consent 的默认开关，均不得渲染为可行动项。 |
| **7. 明确不得证明的事项** | 温暖界面、进度条、品牌表达、案例语言或视觉完成度不证明服务有效、家庭改善或数据治理充分。 |
| **8. 独立 App Gate 裁决问题** | 是否批准“App 为主、Web 为辅”的信息架构原则？第一条纵切的页面是否仅限入口、确认、候选、决定、过程、回访与私有摘要？ |

## 12. 候选纵切优先级：只作为裁决输入

| 候选 | 业务意图 | 可复用基座 | 当前建议 | 原因 |
|---|---|---|---|---|
| C1：亲子沟通紧张时的当下支持 | 问题入口、家庭决定、可暂停下一步 | Need、Intent、Resource Gate、Decision、Plan/Case、FollowUp、handoff | **首选候选；不执行** | 与现有可信纵切重合度最高，可保持文本、私有、确定性。 |
| C2：家庭私有服务过程摘要 | 服务档案/客户后台 | Context Reuse、progress、consent gate | 作为 C1 的只读延伸候选 | 不需要公开/商业化，但须先确定家庭可读字段。 |
| C3：低负担家庭行动节奏 | 21 天挑战/每日任务 | Plan/Case 仅部分复用 | 远期设计 | 容易引入通知、激励、行为监测和效果暗示。 |
| C4：家庭自填服务偏好 | 测评/成长报告入口 | 仅有 consent/Need 基础 | 远期设计 | 可能演化为诊断、画像和敏感数据收集。 |
| C5：公开社群/分享/邀请 | 裂变与城市网络 | 无安全基座 | HOLD | 公开范围、未成年人、激励、审核和跨家庭风险未解决。 |
| C6：会员/咨询/活动/生态 | 长期商业化 | 无授权运行时 | HOLD | Payment/Entitlement/Delivery/组织协作均未授权。 |
| C7：AI 顾问/陪练 | AI 长期陪伴 | 仅 Principal 安全底座 | HOLD | 外部模型、训练、画像、自由文本与治理尚未获准。 |

## 13. 独立 App Gate 最小裁决表

| 裁决维度 | 需要架构师确认的最小问题 |
|---|---|
| 纵切范围 | 是否只允许 C1，且 C2 仅作为只读候选，不开启 C3–C7？ |
| 体验面 | 是否同意 App-first 原则，但第一阶段只做移动视口/响应式内部验证，而不启动原生移动端 runtime 或 Web HOME？ |
| API / 数据 | 是否确认优先复用既有 API，任何 DTO/API/数据库新增必须单独列项并再次裁决？ |
| 家庭边界 | 是否确认 Need、Intent、Decision、Case、FollowUp 和历史摘要只服务当前家庭/child subject，不写成长结果？ |
| 资源边界 | 是否确认只展示已准入资源，PRACTICE 无 executor 不可见，E1 只显示来源/版权事实？ |
| AI / 多模态 | 是否确认第一条 App 纵切不启用外部模型、训练、语音、图像、截图或视频输入？ |
| Human Gate | 是否确认 REVIEW/HIGH_RISK 只显示安全等待状态，不转发给真人、不创建预约或服务承诺？ |
| 验证 | 是否要求真实 PostgreSQL、移动视口浏览器、文本等价、10 类负例、浏览器后回归和静态审计全部通过？ |
| 退出条件 | 是否确认一旦出现支付、公开分享、组织访问、真人服务、跨家庭、成长结果或真实数据导出诉求即停止并新建 Gate？ |
