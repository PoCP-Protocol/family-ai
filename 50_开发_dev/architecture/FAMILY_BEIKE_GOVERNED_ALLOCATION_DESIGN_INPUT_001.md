# Family 贝壳式受治理分配机制：设计输入 001

> **状态：`DRAFT_FOR_APP_GATE_DECISION_INPUT`。**
>
> **性质：架构/体验设计输入，不是组织网络、服务市场、线索分发、竞价、佣金、支付、真人服务或跨家庭推荐的实现授权。**
>
> “贝壳式”在 Family 中只能借鉴**将复杂服务拆解为可验证阶段、按明确资格路由、保留责任追溯、用规则而非暗箱分配解决协作问题**的方法。贝壳 ACN 的组织角色、跨机构协作、服务者评分、收益分配和行业生态不自动适用于儿童与家庭数据场景。[1]

## 1. 需要加入商业内核图的第五能力

建议在“拼多多增长机制 × 字节分发系统 × 海底捞服务体验 × 教育行业长期陪伴”后，加入：

> **贝壳式受治理分配机制：让需求在明确规则下找到合格的下一步，而不是让家庭成为被争抢、被竞价或被暗箱分流的线索。**

面向用户的图中文字建议保持克制：

| 维度 | 建议表达 |
|---|---|
| 名称 | **贝壳式｜受治理分配机制** |
| 用户价值 | 需求不被遗忘；每一步都有依据；家庭始终可选择、暂停或拒绝。 |
| 平台能力 | 需求—能力—资源—服务阶段的资格路由、可见限制、责任追溯和异常停止。 |
| Family 核心 | **让家庭在可信规则下获得合格的下一步。** |
| 明确不是 | 销售线索分配、竞价排名、服务者抢单、佣金结算、跨家庭画像匹配。 |

## 2. 八项功能拆解

| 拆解项 | Family 设计输入 |
|---|---|
| **1. 原始功能/页面线索** | 用户提供的商业内核图已含“用算法匹配需求”；贝壳 ACN 案例的可迁移部分是把复杂服务拆为清晰阶段、以标准与规则约束协作、让责任与过程可追溯。[1] |
| **2. Family 可迁移能力候选** | **家庭私有受治理路由（Governed Family Routing）**：`Need → Intent → Capability → admitted Resource → Family Decision → T2 → Plan/ServiceCase → FollowUp/Handoff`。路由的作用是筛掉不合格下一步、说明当前限制、为家庭提供选择，不替家庭决定。 |
| **3. Consent / 隐私 / 数据边界** | 只使用当前 `family_id`、服务端派生 subject、当前 Need/Intent、资源准入事实、有效 SERVICE consent 与安全状态。不得读取其他家庭、服务者排名、机构库存、地理位置、商业价值、历史转化率或隐性画像。 |
| **4. 风险路由与 Human Gate** | REVIEW/HIGH_RISK 进入扣留/handoff trace，而非自动转给人；无资源、无 executor、T2 失效、consent 撤回、资格不清、需要组织/真人/付费服务时停止并要求新 Gate。 |
| **5. 文本等价路径** | 家庭在文本中看到：当前需要、候选为何可见/不可见、资源限制、可选“暂不行动”、决定后的下一步、等待状态和暂停路径。没有图表、地图、算法分数、服务者排行或语音/图像输入也可完整完成。 |
| **6. fail-closed 条件** | 缺可信家庭上下文、SERVICE consent、年龄资格、T1/T2、资源 admission/copyright/risk、real Practice executor、Family Decision、幂等键、可解释状态时：不分配、不推荐、不创建 Case、不外发。 |
| **7. 明确不得证明的事项** | 分配/路由不证明需求理解正确、资源有效、孩子会改变、服务已交付、家庭画像准确、服务者优劣、系统公平、治理充分或商业化可放行。 |
| **8. 独立 App Gate 裁决问题** | 是否批准首阶段仅以“家庭私有确定性资格路由”呈现候选与限制？是否禁止任何跨家庭/组织/服务者排序？是否将异常场景限定为安全等待，而不建立真人派单？ |

## 3. Family 路由对象模型：可迁移与不可迁移

| 贝壳式方法元素 | Family 可迁移转译 | Family 当前禁止的对应物 |
|---|---|---|
| 服务阶段拆解 | Need、Intent、Resource、Decision、Plan、Case、FollowUp/Handoff 的明确状态机 | 将孩子/家长人格、成长阶段或商业价值切分为永久标签。 |
| 角色/责任清晰 | Named Action、家庭角色、系统责任、Human Gate 的审计可追溯 | 经纪人/顾问/机构的抢单、佣金分成、组织成员评分。 |
| 标准化资格 | Consent、年龄、resource admission、T1/T2、executor readiness、idempotency | 以转化率、付费能力、传播能力或行为画像决定优先级。 |
| 过程留痕 | Decision、Case、FollowUp、handoff、audit/outbox | 对真实家庭进行跨平台追踪、秘密评分或行为监控。 |
| 争议/异常治理 | fail-closed、拒绝码、暂停、撤回、Human Gate | 自动仲裁家庭关系、自动派给真人或外部机构。 |
| 质量约束 | provenance、evidence tier、版权、风险、admission 公开最小摘要 | 用 E1 自家材料自证效果、以结果承诺推动选择。 |

## 4. 受治理分配的状态与责任表

| 路由节点 | 系统可做 | 家庭可做 | 系统必须不做 |
|---|---|---|---|
| Need | 接收最小文本、做家庭/Consent/年龄范围校验 | 描述当下需要或退出 | 推断诊断、形成画像或自动转发。 |
| Intent | 记录家庭确认的服务意图 | 修改、确认或退出 | 替家庭设定目标。 |
| Capability | 在当前家庭范围内说明能力边界 | 理解限制 | 使用跨家庭数据推断或扩大用途。 |
| admitted Resource | 仅返回已准入且当前合格候选 | 查看限制、选择或不选 | 展示降级/未授权/无 executor 资源。 |
| Decision | 记录明确 ACCEPT/alternative/DISMISS | 最终决定或暂不行动 | 自动接受、暗中替换、创建服务承诺。 |
| T2 / Case | 再检资格、形成声明性过程状态 | 查看、暂停、回访 | 将 Case 当作真人服务或效果结果。 |
| Handoff | 留存安全等待与可审计 trace | 看见非承诺性等待状态 | 派单、预约、传输家庭数据或声称已响应。 |

## 5. 与商业内核其余四项能力的关系

| 能力 | Family 的受治理解释 | 贝壳式机制的约束作用 |
|---|---|---|
| 拼多多增长 | 未来仅研究价值驱动的自愿传播，不实现裂变/奖励 | 禁止把家庭路由转成线索归因、邀请任务或激励分配。 |
| 字节分发 | 当前为家庭私有、可解释、资格优先的候选展示，不是算法推荐 | 禁止黑箱排序、跨家庭学习、点击/付费驱动的分配。 |
| 海底捞体验 | “知道下一步、被尊重、可暂停、可找到人”的体验意图 | 异常只进入安全等待，不虚假承诺真人服务。 |
| 长期陪伴 | 服务过程连续性和家庭私有摘要 | 不将过程历史变成永久画像、权益资格或续费压力。 |
| 贝壳式分配 | 需求—能力—资源—服务路由与责任追溯 | 每一跳必须有资格、理由、家庭选择和 fail-closed。 |

## 6. C1 候选纵切中的最小展示方式

在“亲子沟通紧张时的当下支持”候选中，受治理分配不应出现“算法为你匹配”“最适合你”“专家已接单”等语言。允许的体验文案仅包括：

> “基于你刚刚确认的需要和当前可用范围，这里是可供你选择的支持方式。你可以选择其中一项，也可以暂不行动。平台不会替你作决定。”

当没有合格候选时，应显示：

> “当前没有符合安全与准入条件的支持方式。平台不会用未经确认的内容替代。你可以暂不行动，或在适用情况下等待安全处理。”

## 7. Human Gate 决策问题

1. 是否接受“贝壳式受治理分配机制”作为 Family 商业内核图的**第五项方法论能力**，其定义仅限需求—能力—资源—服务路由与责任追溯？
2. 是否确认第一阶段不得出现服务者/顾问/机构分配、抢单、竞价、佣金、排行、组织库存、地理位置或跨家庭数据？
3. 是否确认候选的默认排序必须是资格/安全优先、家庭可解释、可选 NO_ACTION，而不是算法效果/转化/付费优先？
4. 是否确认任何真实人工服务承接、组织协作、预约、转介、AccessGrant 或交付状态均需独立 Gate？
5. 是否将“无法解释、无法取得同意、无法证明准入、无法完成 T2”定义为强制 fail-closed？
