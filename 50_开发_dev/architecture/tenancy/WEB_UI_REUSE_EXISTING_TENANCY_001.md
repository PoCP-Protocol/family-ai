# Web UI 复用现有多租户能力说明

## 决策

Web 前端**不创建**新的 Tenant、Organization、Brand、Role 或家庭授权本体。它直接适配 Family 现有的数据与授权边界：`tenant_family_bindings` 决定家庭归属租户；`tenant_policy_profiles` 决定租户有效策略；账户成员资格与 Bearer 令牌建立调用者身份；Family Scope Guard 和领域权限策略在服务端执行家庭对象级授权。

## Web 租户上下文

| Web 需要呈现的上下文 | 现有来源 | Web 职责 | 禁止行为 |
|---|---|---|---|
| 当前租户 | `tenant_family_bindings.tenant_id` | 显示当前品牌、城市/组织视图和可访问的供给/内容范围 | 前端伪造租户授权或以查询参数绕过服务端校验。 |
| 当前家庭 | Account membership + Family Scope Guard | 显示已授权家庭工作台和资产 | 跨家庭读取、缓存或比较。 |
| 服务供给 | tenant-scoped provider/offering/slot | 呈现当前租户可用专家、服务和时段 | 读取其他租户的供给或自行创建服务事实。 |
| 租户策略 | `tenant_policy_profiles` | 呈现当前租户的交付、可见性和服务规则摘要 | 在 Web 端自行裁决高风险策略。 |
| 角色导航 | 既有账号、成员资格与服务端权限 | 隐藏无权限页面并显示工作台入口 | 把前端菜单隐藏当作授权。 |

## 首批 Web API 适配要求

正式 Web 不能依赖静态 demo 数据作为运行时真相。首批需要在已有 Family API 基础上补足只读、tenant-scoped 投影端点或复用已存在端点：当前角色与租户上下文、当前租户家庭工作队列、交付计划队列、服务供给/待确认需求、内容审核队列、权益/资产摘要和运营指标。所有端点必须以 Bearer 令牌和服务端对象级授权为准。

## Web 角色与页面

| 角色 | 首批页面 | 数据范围 |
|---|---|---|
| 平台管理员 | 租户运营总览、策略状态、风险队列 | 仅平台被明确授权的汇总投影。 |
| 租户管理员 | 家庭队列、交付、服务、内容、资产和租户设置 | 当前 `tenant_id` 的已授权聚合。 |
| 运营负责人 | 激活、交付、权益、活动与内容审核队列 | 当前租户运营投影。 |
| 家庭顾问/专家 | 已分配家庭、服务需求、可用时段和服务回读 | 已分配或明确授权的家庭/服务对象。 |
| 家庭成员 | 与 App 一致的家庭工作台、计划、任务和资产 | 当前家庭范围。 |

## 开发顺序

第一轮以 Web 控制台的桌面信息架构和既有权限/租户语义为基础；第二轮以真实 tenant-scoped read projection 替换开发演示数据；第三轮才接入受控命令、服务履约、权益和内容审核。支付、真实导出、外部分享、自动权益开通和公开社区发布不属于首批 Web 写入范围。
