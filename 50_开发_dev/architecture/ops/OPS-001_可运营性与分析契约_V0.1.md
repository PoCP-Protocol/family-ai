## 0. 契约性质与边界(先立边界)

本文件是 **Metric Contract + Pilot Measurement Contract**,只定义 **WHAT / EVENTS / DECISION_RULE_STRUCTURE**,承接 Roadmap V3.3 中 `M3-W0 · BM-0` 的定调:**不做 Dashboard、不做可视化实现、不改任何 canonical 语义**。

- **只定义,不实现**:本契约不新增/修改 ProductEvent 的 canonical schema,不写入 Ontology,不改 Named Action。`canonical_semantic_changes = 0`。
- **口径来源**:全部指标锚定 `10_规格_spec/04_实施计划/Family_M0_M6_Roadmap_V3.3.md`(L66 旅程链、L91–97 试运行信号)与 `PLAN_SSOT_V3.3 §D6 POST_PILOT_EXPANSION_DECISION_FRAMEWORK`。本契约不新造指标语义。
- **证据纪律**:所有目标值/阈值均为 **Hypothesis(假设)**,溯源 `unverified`,须由 100-Family Pilot 的真实行为数据校准,**不得当作 Fact**。本契约只设"待验证阈值占位 + 裁决规则结构",不宣称任何数值成立。

## 1. 硬规则内建(护栏,非提醒)

以下约束是本契约的**结构性禁止项**,任何下游 Analytics/Ops 实现若违反即视为不合规:

| 编号 | 禁止/约束 | 说明 |
|---|---|---|
| G1 | **不做 Family Total Score** | 禁止把任何指标聚合成"家庭总分"。指标只描述**行为样态**,不评价家庭优劣。 |
| G2 | **不做家庭 Ranking** | 禁止家庭之间横向排名/百分位竞赛。分段(segmentation)仅用于运营诊断,不得回流为对家庭的评级。 |
| G3 | `Recommendation != Decision != Action` | 提案、人工确认、执行是**三个独立事件**,分别计数,禁止合并统计造成"AI 直接行动"的假象。 |
| G4 | `Hypothesis != Fact` | 阈值/目标/北极星均为待验证假设,标注 `provenance=unverified`。 |
| G5 | **PIPL / 未成年人脱敏** | 分析层只消费**聚合/脱敏**数据;禁止落地未成年人可识别画像;涉未成年人分段须 k-匿名(k≥ 待定,Pilot 前定)。 |
| G6 | **Outcome != Signal != Fact** | `observable_outcome_signal` 只是"出现了可观察信号",不等于成长结果成立,更不等于因果结论。 |
| G7 | **不训练/不建模** | 本契约不触发 World Model / Causal Engine / 任何 SFT/LoRA(均 HOLD/FUTURE)。 |

## 2. 事件底座(EVENTS)

所有指标从既有 **ProductEvent** 治理底座派生(Roadmap M3-W0 `ProductEvent / ModelRun / SafetyCase governance`)。本契约**提议**下列 instrumented event 锚点,须与既有 ProductEvent canonical 定义对齐后方可实现(对齐动作属后续任务,不在本 PR 内改 schema):

```
E_WAF_COMPLETED            家庭完成 WAF(进入旅程门槛)
E_PRINCIPAL_QUERY          Famili Principal 收到一次家庭发起的 query
E_PRINCIPAL_RESPONSE       Principal 完成一次应答(含 safety pre/postcheck 结论)
E_ACTION_PROPOSAL          产生一条 Action Proposal(Recommendation 层)
E_HUMAN_CONFIRM            人工确认一条提案(Decision 层)
E_ACTION_EXECUTED          Action Bridge 经 Growth OS 执行完成(Action 层)
E_CHECKIN_SUBMITTED        家庭提交一次 Check-in / Reflection
E_OUTCOME_OBSERVATION      记录一次 OutcomeObservation(信号级,非结论)
E_TIMELINE_RETURN          家庭在旅程后再次进入(Return)
```

> 事件命名为契约**提案**;实现前必须核对 `50_开发_dev` 内既有 ProductEvent 注册,避免重造(NOT_HELD 原则)。

## 3. 四组指标(WHAT + DECISION_RULE_STRUCTURE)

每组指标统一结构:`定义 → 事件来源 → 单位/窗口 → 分段 → 决策规则结构(阈值=待 Pilot 校准的假设)`。

### 3.1 Activation Metric(激活)— 满足 `activation_metric_defined`

- **定义**:家庭是否真正进入并跑通旅程首环——从 WAF 完成到发起首次 Principal query。
- **事件来源**:`E_WAF_COMPLETED` → `E_PRINCIPAL_QUERY`(首次)。
- **主指标**:
  - `activation_rate = |完成 WAF 且发起首次 Principal query 的家庭| / |完成 WAF 的家庭|`
  - `time_to_first_principal_query`(WAF 完成 → 首次 query 的时延分布,报告中位数与 P90)
- **窗口/单位**:家庭为主体;激活窗口 = 待定(Pilot 前设,建议假设 ≤ 首次 WAF 后 T_act 天)。
- **分段**:入口来源 / 生命阶段(粗粒度,受 G5 约束)。
- **决策规则结构(Hypothesis)**:`IF activation_rate < θ_act THEN 判定"进入门槛过高" → 触发旅程首环诊断`。θ_act 为 **unverified 假设**,由 Pilot 校准。

### 3.2 Principal Metric(智能被真实使用)— 满足 `principal_metric_defined`

- **定义**:Famili Principal 被家庭真实、反复使用,且应答安全可用。锚定 Roadmap `principal_query_frequency`。
- **事件来源**:`E_PRINCIPAL_QUERY` / `E_PRINCIPAL_RESPONSE`(含 ModelRun + SafetyCase 结论)。
- **主指标**:
  - `principal_query_frequency = Σ E_PRINCIPAL_QUERY / (活跃家庭数 × 时间窗)`
  - `principal_response_completion = |E_PRINCIPAL_RESPONSE 成功| / |E_PRINCIPAL_QUERY|`
  - `safety_gate_pass_rate`(pre/postcheck 通过率;失败即进 Human Handoff,单独计数,受 G3 约束不计为"完成")
- **窗口/单位**:每活跃家庭每周。
- **决策规则结构(Hypothesis)**:`IF principal_query_frequency 持续下降 AND response_completion 达标 THEN 判定"价值/触达"问题而非"质量"问题`。阈值 unverified。

### 3.3 Action Acceptance Metric(提案被采纳并完成)— 满足 `action_acceptance_metric_defined`

- **定义**:严格区分 Recommendation / Decision / Action 三层(G3),分别度量提案被人工确认、确认后被执行完成。
- **事件来源**:`E_ACTION_PROPOSAL`(Recommendation)→ `E_HUMAN_CONFIRM`(Decision)→ `E_ACTION_EXECUTED`(Action)。
- **主指标**:
  - `proposal_acceptance = |E_HUMAN_CONFIRM| / |E_ACTION_PROPOSAL|`(锚定 Roadmap `proposal_acceptance`)
  - `action_completion = |E_ACTION_EXECUTED| / |E_HUMAN_CONFIRM|`(锚定 `action_completion`)
  - 三层漏斗必须**分事件呈现**,禁止用 `proposal→executed` 直连比率掩盖人工确认这一 Decision Gate。
- **决策规则结构(Hypothesis)**:`IF proposal_acceptance 低 THEN 提案相关性问题`;`IF acceptance 高 BUT action_completion 低 THEN 执行摩擦/能力缺口`。阈值 unverified。

### 3.4 Check-in & Return Metrics(复访与观察回流)— 满足 `checkin_return_metrics_defined`

- **定义**:家庭是否形成"提交观察 → 回流 → 再次进入"的可持续回路,并产生可观察结果信号(非结论,G6)。
- **事件来源**:`E_CHECKIN_SUBMITTED` / `E_OUTCOME_OBSERVATION` / `E_TIMELINE_RETURN`。
- **主指标**:
  - `checkin_submission_rate = |提交 Check-in 的家庭| / |进入 Check-in 环节的家庭|`
  - `return_rate = |旅程后 T_ret 天内再次进入的家庭| / |完成旅程的家庭|`(锚定 Roadmap `return_rate`)
  - `observable_outcome_signal_rate = |存在 OutcomeObservation 信号的家庭| / |活跃家庭|`(信号级,明确 `signal != outcome != fact`,G6)
- **决策规则结构(Hypothesis)**:`IF return_rate ≥ θ_ret AND observable_outcome_signal_rate 上行 THEN 支持"旅程可持续"假设(仍需因果验证,不得直判)`。阈值 unverified。

## 4. 与试运行裁决框架的接口

本契约的四组指标是 `POST_PILOT_EXPANSION_DECISION_FRAMEWORK`(PLAN_SSOT_V3.3 §D6)的**输入信号**,不是裁决本身。

- 指标 → 假设检验 → §D6 裁决流程 → 扩张/收敛决策。
- 本契约**不做**扩张裁决,不设自动扩张开关(evidence-driven,人工 Gate)。
- Roadmap L88 的 `DEFER_POST_PILOT` 能力(need_frequency / pain_intensity 等)其启动依据由本契约的 Pilot 证据提供,而非 Roadmap 时间。
