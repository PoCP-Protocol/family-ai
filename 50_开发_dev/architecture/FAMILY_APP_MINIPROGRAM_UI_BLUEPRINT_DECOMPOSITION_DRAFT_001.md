## 1. 蓝图所表达的最终产品愿景

三组 UI 共同表达的不是一个单点工具，而是一套面向家庭长期成长的体验：家庭可在 App/小程序中认识当下需要、选择可行支持、做出家庭决定、按低压力节奏执行、感受被陪伴，并在未来（经独立授权）获得服务、内容、活动与商业关系。

> **Family 的实现原则：先把“可信家庭支持闭环”做好，再逐项开启诊断、任务、陪跑、分享和商业。**

| 蓝图组 | 原始页面线索 | 最终体验意图 | Family 当前转译 |
|---|---|---|---|
| 组 A：小程序主闭环 | 首页、家庭测评、AI 成长诊断、90 天成长方案、陪跑服务、我的/会员中心 | 从进入到方案、交付与长期陪伴 | 拆为“家庭私有支持闭环”与多个独立 Gate。 |
| 组 B：增长优化场景 | 家庭体检、AI 报告、每日任务、孩子端助手、排行榜、成长海报/分享 | 降低进入门槛、持续使用、孩子参与与传播 | 家庭入口/低负担行动可研究；AI、排行榜、分享继续 HOLD。 |
| 组 C：裂变商城 | 商城、商品详情、邀请有礼、拼团、积分、会员/收益 | 获客、交易、权益和复购 | 全部作为商业架构输入，当前禁止实现。 |

## 2. App-first 与小程序的双入口原则

| 维度 | App（主） | 小程序（辅） | 当前 Gate 结论 |
|---|---|---|---|
| 核心角色 | 已信任家庭的长期私有空间、服务过程与连续性 | 轻入口、说明、可控转入主体验 | 先做 App-first 任务契约；小程序不自动获得数据或功能。 |
| 数据范围 | 家庭私有、有效 consent 下的最小服务过程 | 默认最小、无会话不显示家庭数据 | 小程序不能成为绕过 Account→binding→membership 的身份后门。 |
| 体验目标 | 可信、低压力、可暂停、可回看 | 清晰、文本可读、无诱导性转化 | 不允许用营销/分享压力替代家庭自主选择。 |
| 未来商业 | 仅在独立 Gate 后呈现合同化权益 | 不能用裂变、拼团或积分诱导处理儿童/家庭数据 | Payment/Entitlement/Marketplace 继续 HOLD。 |

## 3. 逐页功能拆解：组 A“小程序主闭环”

### A1. 首页 / 家庭成长平台

| 八项拆解 | Family 设计输入 |
|---|---|
| 1. 原始功能/页面线索 | 问候语、免费家庭测评、AI 诊断、21 天挑战、90 天计划、成长案例、家庭直播/专家咨询、今日成长任务、推荐内容/服务、底部导航。 |
| 2. 可迁移能力候选 | **家庭私有欢迎页**：文本化隐私说明、当前可继续的服务过程、一个“说说现在需要”入口、已准入资源/计划摘要、暂停与退出。 |
| 3. Consent / 隐私 / 数据边界 | 只显示当前家庭已存在的最小服务过程；不展示孩子画像、分数、案例、转化文案或跨家庭内容；任何 history 依赖有效 SERVICE consent。 |
| 4. 风险路由与 Human Gate | 无有效会话、ambiguous context、consent 撤回、无资格资源时，显示安全入口或空状态；不跳转到测评、聊天、真人或商城。 |
| 5. 文本等价路径 | 所有卡片、状态、进度、CTA 均有文本；不依赖插画、颜色、动效或小程序原生组件。 |
| 6. fail-closed 条件 | 不可信会话、无家庭范围、资源降级、外部模型未授权、内容来源不明时不显示可行动入口。 |
| 7. 不得证明 | 首页存在、任务进度、推荐卡或服务摘要不证明家庭已改善、孩子已成长、资源有效。 |
| 8. 独立 App Gate 问题 | 是否允许首页仅展示既有服务过程和“表达当前需要”，不含测评、AI、挑战、案例、直播、商城或咨询？ |

### A2. 家庭测评 / 家庭成长体检

| 八项拆解 | Family 设计输入 |
|---|---|
| 1. 原始功能/页面线索 | “3 分钟了解孩子成长状态”、多题步骤、亲子沟通/学习习惯/情绪管理/自律能力/手机依赖等维度、补充年龄/家庭情况。 |
| 2. 可迁移能力候选 | 当前最多研究**家庭自填的服务偏好确认**，用于表达“本次想讨论什么”，而不是测评孩子或产生综合分数。 |
| 3. Consent / 隐私 / 数据边界 | 每类问题必须有独立目的、最小字段、保存期限、儿童/第三方保护和撤回路径；不收集不必要敏感信息。 |
| 4. 风险路由与 Human Gate | 涉及心理健康、危机、诊断、第三方叙述、儿童高敏感数据时停止；需要专家、模型或人工复核时另行 Gate。 |
| 5. 文本等价路径 | 简短文字问题、可跳过、保存前说明、退出；不要求图像、语音、视频、身份证明或定位。 |
| 6. fail-closed 条件 | 未定义 purpose/consent/保留期/人工责任时，不收集、不计算、不产生报告、不写标签。 |
| 7. 不得证明 | 自填问题、选择项或量表答案不证明孩子能力、家长风格、风险水平或教育结果。 |
| 8. 独立 App Gate 问题 | 是否单独授权非诊断、可撤回的家庭服务偏好问卷设计？任何“测评报告”是否必须另立 Gate？ |

### A3. AI 成长诊断报告

| 八项拆解 | Family 设计输入 |
|---|---|

| 2. 可迁移能力候选 | 可保留的仅是**家庭可读服务过程摘要**：当前确认的需要、家庭已作决定、下一步与可选主观回访；不使用“诊断”“综合分”“优势/风险画像”。 |
| 3. Consent / 隐私 / 数据边界 | 不自动合成孩子画像；不把自由文本、跟踪数据或家庭互动写入核心 ontology；不产生永久特征。 |

| 8. 独立 App Gate 问题 | 第一条 App 纵切是否明确禁止评分/图谱/画像，并只允许服务过程摘要？未来受控模型的输入、输出、人工复核如何裁决？ |

## 7. 贝壳式受治理分配如何贯穿 UI 蓝图

UI 不应展示“算法最懂你”或“专家已接单”的黑箱承诺。它应在每一个家庭页面明确：当前下一步来自哪些**可验证约束**，家庭能否选择/拒绝/暂停，以及何时系统因安全与资格原因停止。

| UI 时刻 | 可见的受治理分配说明 | 禁止文案/行为 |
|---|---|---|
| Need 输入后 | “根据你确认的需要，平台只会显示当前安全且已准入的支持方式。” | “AI 已精准诊断你的孩子。” |
| 候选展示 | 来源、适用限制、风险/准入摘要、“暂不行动” | “最适合你”“成功率最高”“限时抢购”。 |
| 决定后 | “这是你的家庭选择；可暂停；服务过程不是成长结论。” | 自动开启任务、自动扣费、自动派给真人。 |
| 无合格候选 | “当前没有可安全提供的下一步，平台不会用未经确认的内容替代。” | 用无来源内容兜底、强推测评/购买/咨询。 |
| HIGH_RISK/REVIEW | “当前请求处于安全处理状态；系统未作自动回复或服务承诺。” | 展示顾问姓名、承诺时限、自动创建预约。 |

## 8. 首个 App Gate 的必备裁决问题

1. 是否确认 App 与小程序蓝图是**长期目标体验**，而不是一次性全量实施清单？
2. 是否仅放行 L1（C1）进入下一轮任务契约设计，L2 作为可选延伸，L3–L7 继续 HOLD？
3. 是否确认首阶段必须零 AI 诊断/报告/评分、零孩子端、零排行榜/分享/邀请、零积分/商城/拼团/会员/订单、零真人服务？
4. 是否确认 App-first 原则仅允许移动视口内部体验验证，仍不等同于原生 App 或小程序 runtime 发布？
5. 是否确认 App 第一阶段复用既有可信 API；任何新 DTO/API/DB/后台任务/通知权限均需要独立列项与裁决？
