# 榜样教育材料：Family App-first 设计输入摘录

> **材料性质与证据上限：E1 自家材料。** 两份 PPT 可证明榜样教育已有的品牌主张、内容资产、服务设想、商业叙事与视觉语言；它们**不能**证明教育效果、用户结果、画像正确性、治理结论或任何能力的运行时放行。

## 一、材料来源与可追溯位置

| 材料 | 页数 | 与 App-first 直接相关的原始表述 |
|---|---:|---|
| 《榜样教育新商业模式》 | 20 | “孩子问题是入口、父母二次成长是价值、家庭改变是结果”；问题触发—觉醒—行动—改变—长期—传播旅程；客户后台、成长挑战、90 天计划、服务档案等。 |
| 《榜样教育战略白皮书》 | 30 | 家庭成长服务、每日可执行/可反馈/可坚持、产品闭环优先、课程/交付/数据/AI 协同、家庭成长旅程、标准化交付。 |

## 二、可继承的 App-first 产品输入

| 材料输入 | App-first 可转化的体验意图 | 当前 Family V3 对齐方式 | 当前禁止的误读 |
|---|---|---|---|
| 孩子现实问题是入口 | 移动端优先提供简短、可暂停的家庭表达入口 | `Need → Intent → Capability → admitted Resource → Family Decision` | 不把问题描述自动诊断为孩子标签或成长结论。 |
| 父母成长是价值 | 面向监护人呈现可理解的家庭选择、下一步和主观回访 | 家庭决定、FollowUp、过程投影 | 不将“父母改变”或“家庭改变”显示为已被系统证明的效果。 |
| 每日小行动 / 21 天挑战 | 后续可研究低负担、文本等价、可暂停的家庭行动节奏 | 现有 Plan / ServiceCase 仅代表明确选择后的声明性服务过程 | 不自动生成任务、连续打卡压力、强制提醒或完成率惩罚。 |
| 90 天陪跑 / 长期陪伴 | 后续可设计阶段性计划和家庭私有进度视图 | Context Reuse、Plan、Case、FollowUp 均受家庭范围与 consent 门禁 | 不实现真人顾问、会员权益、自动续费或跨家庭运营。 |
| 服务档案 / 客户后台 | 家庭可见的私有服务过程、已选择资源、主观感受和撤回状态 | Family 作为数据所有权根；Phase 10 生命周期和 Context Reuse 已有最小边界 | 不显示内部 UUID、隐藏数据、第三方资料、永久画像或成长评分。 |
| 课程 / 成熟内容资产 | 已准入资源可作为家庭自主选择的候选输入 | Resource Asset Gate、来源/版权/evidence/admission/risk 约束 | E1 材料不展示为“证明有效”；未准入或降级资源 fail-closed。 |
| 线上效率 + 线下信任 | 后续可以设计“请求人工帮助 / 等待人工确认”的透明状态 | Principal REVIEW/HIGH_RISK handoff 保留 traceability | 不开启真人顾问交付、预约、组织协作或服务市场。 |
| 分享 / 社群 / 城市网络 | 仅记录为远期策略设计输入 | 无当前运行时对应 | 不实现公开分享、邀请奖励、社区、城市圈、分销、积分、权益或跨家庭分析。 |
| AI 陪伴 | AI 只应位于受控服务闭环中，不应成为 UI 的夸大主张 | P0 已要求严格 Consent、Human Gate、V3 proposal delta=0 | 不外呼未授权模型，不训练/自学习，不把自由文本写入核心 ontology。 |

## 三、视觉与交互调性观察

两份材料使用深藏蓝/近黑封面与浅色主体页的节奏。封面强调克制、信任和长期方向；正文以大留白、清晰标题、蓝色分隔线、表格/阶段旅程/卡片说明承载信息。商业模式材料增加了低饱和浅蓝背景、深蓝表头以及少量暖橙和暖黄作为“行动/重点”提示；战略白皮书更简洁，以深色结论页和白底结构页交替。

因此，未来 App-first 体验建议继承的是**温暖、克制、可信、可解释**，而不是将 PPT 的商务表格直接搬到手机。手机界面应采用单一当下任务、家庭可读语言、充足留白、低刺激状态提示、清晰暂停/返回入口与文本等价路径。深蓝可用于账户安全、重要确认和夜间高风险提示；浅暖色只用于非操纵性的进度、提醒或资源卡片，不可用于制造焦虑或诱导购买。

## 四、必须在 App Gate 中显式反转或暂停的材料表述

| 原始商业/战略表达 | Family App Gate 的治理处理 |
|---|---|
| “家庭画像”“AI 越用越懂家庭”“成长数据库” | 改写为家庭私有、可见、可撤回、最小化的服务过程事实；不形成永久画像、隐性推断或跨家庭学习。 |
| “家庭改变是结果”“可见变化”“结果案例” | 仅可记录家庭主观帮助感、选择和过程状态；不得生成因果效果或儿童成长结果。 |
| “AI 诊断”“AI 推荐”“AI 陪伴” | 必须走独立 Model Gateway / Consent / Evidence / Human Gate；当前 App Gate 不启用外部模型。 |
| “成长报告、分享、社区、身份等级、邀请权益” | 公开分享、社区、身份、积分、权益和邀请功能全部 HOLD；不得以增长目的改变儿童/家庭数据边界。 |
| “咨询、沙龙、城市活动、专家服务、生态层” | 真人顾问、组织访问、预约、支付、Enrollment/Delivery、Marketplace 和生态交易继续 HOLD。 |
| “会员、订阅、订单资产、奖励” | Payment、Entitlement、会员、订单、佣金和结算继续 HOLD；仅保留未来业务设计输入。 |

## 五、下一阶段 Gate 应回答的问题

App-first Gate 草案必须给出正/负清单、一个家庭用户旅程、页面范围、DTO/API 影响、数据与 Consent 边界、文本等价、多模态入口前置条件、fail-closed 负例、真实 DB/E2E 验证矩阵、退出条件和 Human Gate 问题。它必须先选择一个可验证的家庭私有服务场景，而不是一次性实现“测评—挑战—社群—会员—生态”的整套商业构想。
