# UI-12 家庭私有成长故事预览 PDCA 001

> **本轮目标**：从 UI-11 的同一家庭过程回看进入 UI-12 的**私有成长故事预览**。故事只整理可解释的家庭过程节点；不生成、保存、下载、外发、分享、通知或公开发布海报；不把过程描述为孩子能力提升、教育效果、因果结论、积分、勋章或称号。

## 1. 基线阅读与不可动态化元素

基线为 `growth-poster-reference-444x970.png`，尺寸 444 × 970px。经两块重叠阅读，上半部包含“成长成果海报”、孩子姓名/年龄/学校、成长周期、叙事性标题、成长前后描述、连续打卡与成长值；下半部延续勋章、二维码、“分享给更多人”按钮以及分享和生成海报入口。

这些名称、年龄、学校、周期、成长前后、连续天数、成长值、勋章、二维码、分享和生成按钮均只作为原图视觉基线，**不会被读取、填充、更新、解释或触发**。动态卡必须追加在基线之后，并且只能展示同一家庭已发生的过程节点与一段不作效果判断的私有回顾。

## 2. 用户需求与最小闭环

家长需要的是一次温和地回看“我们一起尝试过什么”的机会，而不是一张证明孩子“变得更好”的海报。UI-12 读取 UI-11 的同家庭过程事件，形成可读的私有故事预览。故事包含一个标题、过程摘要和一句“下一步”提示；只可返回 UI-11 成长旅程，不提供保存、下载、分享、发送、公开发布或生成媒体的动作。

| 用户问题 | UI-12 回答 | 明确不做 |
|---|---|---|
| “我们可以怎样记住这段尝试？” | 把已发生的选择、计划、行动和回顾组织成私有过程叙事。 | 不把过程叙事称作成果或效果。 |
| “可以发给别人吗？” | 本轮不提供外发入口；先在家庭内回看。 | 不分享、通知、下载、生成二维码或发布。 |
| “孩子有没有进步？” | 不从事件推断能力、表现、结果或因果。 | 不显示成长前后、天数、分值、勋章或称号。 |

## 3. 实现与验收边界

平台投影只接受认证家庭的 UI-02、UI-04、UI-05、UI-09 流程事件；返回 `private_growth_story` 只读字段，并带有 `PROCESS_EVENTS_NOT_OUTCOME_OR_SHARE` 边界。空态提醒家长从一件愿意关注的小事开始；有事件时显示不超过四个过程节点。页面对象、服务和集成测试必须断言用户字段不含儿童识别信息、分数、勋章、效果或分享字段，且唯一入口只回到 UI-11。

## 4. 研究依据与设计决定

家庭故事能够帮助成员把各自的经历组织成共同理解，但叙事始终是对经验的一种选择和解释，不能被系统自动升级为事实、效果或因果结论。[1] 学习故事的实践也强调观察、反思、家庭观点与下一步支持；其目的不是验证假设或给孩子贴标签。[2] 因此，本轮故事只从受控过程事件写出“发生了什么”，不添加“孩子变得怎样”的解释，也不处理儿童照片、姓名、年龄、学校、音视频或任何外发动作。

| 设计决定 | 实现方式 |
|---|---|
| 私有而非分享 | 不返回分享链接、二维码、下载、通知、发布、收件人或媒体字段；唯一入口回到 UI-11。 |
| 过程而非结果 | 仅可使用选择关注方向、查看计划、打开行动和打开回顾等事件。 |
| 共同理解而非替代发言 | 文案使用“我们尝试过”“可以回看”，不声称儿童的感受、能力或变化。 |
| 不采用裸模型生成 | 不调用模型；仅用规则化模板组织已记录过程。 |

## 5. 浏览器复核准备

已在刷新后的本地 UI-12 会话挂载同一家庭过程事件测试投影。私有故事卡只包含三条过程片段和“回到成长旅程”入口；不包含姓名、年龄、学校、照片、分数、勋章、二维码、保存、下载、分享、发布或通知字段。原始海报画布保持完整可见。

刷新后再次挂载测试投影。最终状态提示为“家庭故事已准备好。可以慢慢回看这些片段。”；动态卡仍只有过程片段和返回成长旅程入口。
