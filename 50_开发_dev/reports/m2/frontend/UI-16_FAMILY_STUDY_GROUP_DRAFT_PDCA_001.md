# UI-16 家庭共学组队草稿 PDCA 001

## 1. 本轮范围

本轮从 UI-14 的内容详情进入 UI-16 的家庭共学组队页面。页面不把静态团购、价格、人数、倒计时或“去拼团”画面解释为真实商业承诺；它只让家长在家庭内部先记下一份“想和熟悉家庭一起学习”的组队草稿，再自行决定是否继续。

| 项目 | 本轮实现 | 明确不做 |
|---|---|---|
| 用户路径 | UI-14 内容详情 → UI-16 共学组队草稿 → 回看家庭意向 | 拉取联系人、外发邀请、群聊、支付、库存锁定、订单、优惠、权益、通知、退款 |
| 数据关系 | UI-14 所选目录条目的引用传入 UI-16；复用已有家庭范围的测试组队操作 | 将静态人数、倒计时、价格、团长或头像转化为动态事实 |
| 用户表达 | “先记下组队想法”“可以之后再决定”“是否邀请由你们自己决定” | “还差几人”“限时”“立即成团”“最低价”“领取权益” |
| 视觉策略 | 完整保留 UI-16 原图，动态草稿卡位于原图之后 | 重绘原图分类、组队进度、价格、团长、成员头像与按钮 |

## 2. 用户需求与设计依据

家长可能希望与熟悉的家庭一起学习、相互提醒或交流经验，但这种支持应是自愿的，并保留家庭对参与节奏、对象和退出的自主决定。家庭中心实践主张向家庭提供完整且尽量中性的信息，以支持其作出知情决定；后续行动由家庭自己选择。[1] 因此，本轮把 UI-16 的实际用户动作设计为“记下组队想法”，而不是默认发送邀请、绑定成员、生成群聊或启动付款。

> “Family-centered practices … provide family members complete and unbiased information to make informed decisions; and involve family members in acting on choices …” — University of Illinois Early Intervention Training Program.[1]

同行支持研究与资源将家庭支持描述为帮助家长取得信息、资源和自主决定支持的方式；本轮仅把这一点作为设计输入，不据此声称本页面能带来任何家庭或儿童结果。[2]

## 3. 基线阅读与保真边界

UI-16 基线图为 `commerce-04-group-buy.png`，尺寸为 244 × 545 像素。可见结构包括分类栏、四张静态组队卡、团长、头像、差几人成团、倒计时、静态原价/团购价和“去拼团”按钮。本轮完整保留该原图。动态层不会读取或解释静态人数、姓名、头像、价格、优惠、库存或倒计时，也不会将其作为组队草稿的前提。

动态卡固定追加在原图之后，只显示“家庭共学想法”、当前目录内容标题、是否已记下草稿与两个用户入口：记下想法、回到内容详情。它不展示真实成员名单、联系方式、群名、进度、价格或交易信息。

## 4. 数据与行动边界

```text
UI-14 selected catalog item
  └─ { product_ref, product_version, title }
       └─ UI-16 group-draft preview
            └─ existing protected DEV/TEST group-draft operation
                 └─ family-scoped operation receipt; no external effect
```

受保护的组队操作在测试环境下记录家庭范围的组队草稿及幂等审计信息。前台只显示“已记下共学想法”，不显示操作名称、环境、审计字段、回执编号或适配器状态。草稿不代表外发邀请、其他家庭接受、付款、库存预留、订单确认、权益发放或服务履约。

## 5. 验收标准

1. UI-14 的“想和熟悉家庭一起学习”入口进入 UI-16；所选目录条目保持一致。
2. UI-16 动态草稿卡只显示当前内容标题、家庭自主决定说明和两个入口。
3. 记下草稿仅调用现有受保护的 UI-16 组队测试操作；其响应必须保持 `external_effect=false`。
4. 动态前台不显示 DEV、synthetic、no-op、模型、审计、内部状态、真实成员、价格、销量、优惠、订单、支付、库存、通知、邀请或分享术语。
5. UI-16 原图保持完整；动态内容位于原图之后。
6. 完成聚焦 API/前端测试、API 与 Web 全量回归、浏览器视觉复核，然后仅提交本轮文档与相关程序。

## 6. 浏览器复核准备

已在刷新后的本地会话挂载同一家庭的目录条目，再从 UI-14 内容详情进入 UI-16 并触发“记下共学想法”。测试响应仅为家庭范围草稿，状态为 `CREATED` 且 `external_effect=false`。接下来以实际移动端渲染检查原始组队图与动态草稿卡的层级、可读性及前台文案。

## 7. 移动端视觉复核

移动端复核确认：UI-16 原始组队基线图完整保留；家庭共学想法卡位于原图之后，清楚显示当前内容“亲子沟通小练习”和“共学想法已记下”。动态区域仅提供“记下共学想法”和“回到内容详情”。它不显示真实成员、联系方式、群聊、价格、优惠、库存、倒计时、订单、支付、权益、邀请发送、分享、下载、发布或工程过程信息。原图中的成员、人数、价格与倒计时保持为未改动的视觉基线，未被读取、解释或写入。
