# UI-05 计划到当周行动 PDCA 001

> **本轮范围**：将 UI-04 已查看的 90 天成长计划预览，衔接到 UI-09 的今天行动。目标是帮助家长把“看过计划”变成一个可开始、可共同完成、可调整的小步骤；不把任务完成视为孩子成长结果，不创建总分、排名、诊断、付款、预约、通知、分享或外部效果。

| 字段 | 本轮定义 |
|---|---|
| `PDCA_ROUND` | `UI05_PLAN_TO_UI09_ACTION_001` |
| `SOURCE_UI` | UI-05（90 天成长计划） |
| `TARGET_UI` | UI-09（今日成长任务） |
| `USER_JOURNEY` | 家长看见本阶段重点 → 选择今天可开始的一项行动 → 与孩子一起尝试 → 记录行动 → 下一次可调整 |
| `CHILD_EXPERIENCE` | 不被评分、不被贴标签；知道今天可以选择或参与的一件小事，遇到困难可暂停、缩小或改期。 |
| `PARENT_EXPERIENCE` | 不面对抽象的 90 天要求；获得一项清楚、时间有限、可替代的当周行动，并能看见与长期计划的关系。 |
| `FAMILY_EXPERIENCE` | 计划不是家长单向下达；行动包含共同选择、倾听和日常节奏的空间。 |
| `WRITE_BOUNDARY` | 仅持久化“从计划查看当周行动”的家庭内流程事件；UI-09 仍由既有 `CompleteGrowthAction` 记录实际行动完成。 |
| `FRONTEND_RULE` | 不显示 DEV、synthetic、模型网关、审核、测试数据、回执或内部命令。 |

## 1. Plan：用户需求与研究输入

UI-05 的基线图是一张 434 × 1130px 的长图，已按纵向顺序完整阅读。上半部包含“90天成长方案”标题、当前阶段和目标、90 天总时长、3 大阶段、12 周计划、36 个任务统计，以及第 1 周的已完成/待完成任务；下半部延续第 2 至第 4 周阶段卡，底部是“开始执行计划”CTA。图中具体任务、完成状态和统计属于提供的视觉内容，不能被改写为本轮家庭的事实、分数或效果判断。

行动计划研究建议把长期目标拆成清楚的“何时、何地、怎样做”的短周期行动，并允许频繁回顾和调整，而不把计划本身当成结果。[1] 家庭惯例资料强调，好的日常安排应适合该家庭、角色清楚、规律而可预期，并随孩子年龄和家庭情况灵活调整；让孩子参与规划有助于其理解和参与。[2] 关于亲子共同调节的研究表明，互动中的支持、回应和灵活调整具有情境性，不能被简化为对儿童的单向评价或固定结论。[3]

因此，本轮不显示任务分数、连续天数的压力性评价或“完成得好/不好”的判断。UI-05 CTA 改为“查看今天的行动”，进入 UI-09 时展示计划来源、当周小行动和可选替代做法；UI-09 完成动作仍只表示已记录行动。

| 用户问题 | 体验回答 | 对应数据关系 |
|---|---|---|
| 家长看完 90 天计划后不知道今天从哪里开始 | 将当前阶段压缩为一件当天可尝试的小行动，并说明它来自哪个关注方向 | `DevGrowthPlanPreview` → `DevWeeklyActionHandoff` → `FamilyTodayProjection` |
| 孩子不希望被计划或评价控制 | 前台使用“今天可以一起试试”的选择式语言；允许替代做法和暂停 | `Perspective` / `Recommendation` 与 `GrowthActionCompletion` 分离 |
| 家庭当天时间不足或情绪不适合执行 | 显示替代做法，不将未完成标为失败 | `fallback_action` 只读推荐；不产生 Outcome |
| 家长希望长计划和日任务是一条线 | UI-09 明确显示“来自本周计划”的上下文，但不覆盖既有真实任务对象 | `family_dev_flow_events` 记录 UI-05 查看事件；`CompleteGrowthAction` 保持独立命名动作 |

## 2. Do：最小实现设计

本轮将在 Core Growth 投影的 UI-05 卡内增加 `weekly_action_handoff`，包含 `focus`、`stage_id`、面向家庭的行动标题、行动说明、替代做法和 UI-09 目标路由。UI-05 的“开始执行计划”视觉触点记录 `OPEN_SYNTHETIC_WEEKLY_GROWTH_ACTION` 后进入 UI-09；该事件表示计划与今天行动页面已被打开，**不是**同意、正式任务创建或行动完成。

UI-09 加载既有 `FamilyTodayProjection` 后，再读取相同家庭的 Core Growth 投影，展示“今天的行动”与计划来源之间的轻量上下文卡。用户最终点击 UI-09 的完成按钮时，仍只调用既有 `CompleteGrowthAction`。如果当天没有开放任务，页面保留现有“暂无待办”状态，同时显示可以从替代做法重新选择的温和提示，而不是伪造完成。

## 3. Check：测试与视觉验收

验收覆盖 UI-05 计划 CTA 的流程事件、幂等回读、相同关注方向在 UI-09 上下文中的透传、无开放任务的自然空态、UI-09 的真实完成动作不产生 Outcome、跨家庭访问失败、前台无工程术语，以及 UI-05/09 基线图不被覆盖。视觉上，动态上下文只能出现在 UI-09 基线下方；UI-05 的原有阶段卡和 CTA 布局不改变。

## 4. Act：本轮提交准则

本轮完成代码、测试和移动端视觉复核后，将只提交 UI-05/UI-09 血缘相关的文档、契约、服务、前端、样式和测试，并推送 GitHub。推送同步完成前不开始其它 UI。下一轮候选为 UI-09 行动记录到 UI-08/29 的家庭回顾与证据边界纵切。
