# UI-22 家庭成长活动目录 PDCA 001

## 用户问题与本轮目标

家长在浏览家庭支持主题后，往往还需要了解是否存在可以一起参与的线下或线上成长活动。活动目录应帮助家庭判断“我想不想进一步看看”，而不是以热度、倒计时或报名压力替代家庭决定。家庭中心实践强调向家庭提供完整、中性的信息，以支持其作出知情选择。[1] [2]

本轮从 UI-19 家庭支持主题目录增加 UI-22 家庭成长活动目录入口。UI-22 仅呈现一组家庭可浏览的活动主题、适龄参考和简短说明，并可进入 UI-23 查看活动说明。浏览不表示报名、占位、到场、日历写入、视频会议、通知、支付或真人服务已经发生。

| 用户 | 需要的体验 | 本轮实现 |
|---|---|---|
| 家长 | 先知道有哪些活动主题，再决定是否进一步了解 | 中性活动主题卡、活动说明入口、可延后决定提示 |
| 孩子 | 不被活动参与量、热度或集体比较定义 | 不展示排名、参与人数、奖励、成果或适配结论 |
| 家庭 | 从支持主题自然过渡到可以浏览的成长活动 | UI-19 → UI-22 → UI-23 的只读信息血缘 |
| 平台 | 验证活动目录与详情的前台血缘，不触发外部副作用 | 规则化目录投影与无写入导航 |

## 数据与状态边界

> UI-19 家庭支持主题 → UI-22 家庭成长活动目录 → UI-23 活动说明。

UI-22 的活动条目为家庭可浏览内容，包含活动主题、简短说明、适龄参考和详情入口。状态只有“可以了解”或“目前先从主题说明开始”，不宣称可报名、已报名、已确认或活动已举行。正式报名、名额占用、日历写入、视频创建、通知、支付、分享和出席记录均不属于本轮。

| 可读内容 | 本轮不生成或不展示 |
|---|---|
| 活动主题、简短说明、适龄参考、详情入口 | 报名确认、名额、参与人数、倒计时、价格、支付 |
| 家庭自己浏览过的主题 | 热度排序、推荐排名、儿童适配结论、效果承诺 |
| 返回支持主题的入口 | 日历、视频、通知、分享、外部联络 |

## 视觉与前台表达

以 `salon-list-reference-466x1008.png` 为 UI-22 基线，动态活动目录位于原图后方。原图中的城市、时间、人数、价格、报名按钮等视觉元素仅保留为静态基线，不转化为动态事实。前台只显示“家庭成长活动”“慢慢了解活动主题”“查看活动说明”等自然产品语言，禁止显示开发过程、测试数据、内部状态或工程术语。

## 验收标准

1. UI-19 支持主题页可进入 UI-22 活动目录；UI-22 能回到 UI-19。
2. UI-22 只提供活动主题的读取与 UI-23 详情导航；不产生 POST、报名、支付、通知、日历或视频请求。
3. UI-22 动态内容不显示排名、热度、人数、价格、权益、倒计时、报名确认、提供者评价或工程术语。
4. 自动化测试覆盖入口血缘、空态、自然错误态、无写入及 UI-01 至 UI-35 全量回归。
5. 移动端复核确认活动目录卡位于原始沙龙列表基线之后，保留原图且动态卡层级清晰。

## Check：移动端视觉复核

在本地体验环的受控同家庭活动投影下，UI-22 原始沙龙页面基线完整保留。家庭成长活动目录追加在原图之后，清晰呈现两个可浏览主题、简短说明、适龄参考与“查看活动说明”入口。动态区域未呈现报名、名额、价格、日历、视频、通知、支付或到场内容；原图内这些元素不构成动态事实或用户承诺。

视觉层级结果为：原始页面 → 家庭活动目录 → 已选活动说明入口 → 回到支持主题。该路径仅产生同页面会话切换，不触发任何写入或外部动作。

UI-23 最终复核确认：活动说明页保留原始活动详情基线，动态说明卡仅复用已选活动的标题、简短说明与适龄参考，并明确是否继续关注由家庭自行决定。动态区域没有报名、支付、预约、通知、日历、视频或到场承诺；唯一可执行入口为“回到活动目录”。
