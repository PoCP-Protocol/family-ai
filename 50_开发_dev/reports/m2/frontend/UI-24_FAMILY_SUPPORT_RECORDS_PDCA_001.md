# UI-24 家庭支持记录概览 PDCA 001

## 用户问题与本轮目标

当家长已经记下一项咨询需求后，最需要的是能回看“已经记下什么、目前仍处于什么阶段、接下来可以做什么”，而不是看到模糊的服务承诺或被迫继续操作。家庭中心实践强调家庭应能够理解记录并参与后续决定；记录应支持解释与共同决策，而非替家庭作出判断。[1] [2]

本轮将 UI-21 的家庭咨询需求接入 UI-24 的家庭支持记录概览。页面只读取当前家庭的咨询需求、活动记录和支持条目，并以“已记下需求”“可以继续了解”“查看支持主题”等中性语言呈现。它不表示真人已排期、已联系、已提供服务、已完成服务或产生任何教育效果。

| 用户 | 需要的体验 | 本轮实现 |
|---|---|---|
| 家长 | 看懂需求是否已被记下以及可以回到哪里继续了解 | 家庭范围只读记录、自然状态文本、支持主题入口 |
| 孩子 | 不被服务记录定义或评价 | 不展示儿童诊断、评分、成果或比较内容 |
| 家庭 | 从已记录需求回到支持说明，而非被迫推进服务 | 返回支持主题与家庭成长计划入口 |
| 平台 | 验证咨询需求到可读记录的同一家庭数据血缘 | 复用受保护客户投影、家庭范围、同意、审计和无外部效果读取 |

## 数据血缘和事实边界

> UI-20 支持说明 → UI-21 家庭咨询需求 → 家庭范围服务请求 → UI-24 家庭支持记录概览。

UI-24 只读取已有客户投影中的 `bookings`、`service_records` 与活动相关记录。前台将 `REQUESTED` 解释为“需求已记下”，将空态解释为“还没有需要回看的支持记录”。不会展示内部记录编号、服务者信息、资格、评价、价格、权益、时段、通知、视频地址、支付或审计字段。

| 可展示 | 不展示或不声明 |
|---|---|
| 已记下的家庭需求、可回看条目、下一步入口 | 已排期、已联系、已通知、已完成真人服务 |
| 家庭自己的支持主题与回看路径 | 服务者身份、资质、评价、排名与比较 |
| 服务记录的中性状态 | 教育效果、成长结论、儿童画像或诊断 |

以 `service-mine-reference-472x1018.png` 为视觉基线，动态记录卡追加在原图后方。原图的咨询、活动、会员、状态、服务者和进入详情视觉均保持静态基线，不转为动态事实。前台仅使用“家庭支持记录”“需求已记下”“继续了解支持主题”“回到成长计划”等自然产品语言，禁止显示 DEV、synthetic、no-op、模型网关、回执、审计、同意、测试数据等工程术语。

## 本轮验收标准

1. UI-21 需求请求成功后，UI-24 能通过同一家庭客户投影回读相应记录。
2. UI-24 动态卡清楚区分“已记下需求”与“尚未安排”，不宣称真人服务已开始、已联系或已完成。
3. UI-24 只发起家庭范围只读 GET；不创建、取消、改期、通知、支付、退款、联系或外部动作。
4. 自动化测试覆盖跨家庭隔离、空态、请求成功态、自然错误态、UI-21→UI-24 血缘和 UI-01 至 UI-35 全量回归。
5. 移动端复核确认动态卡位于原始服务记录基线之后，且动态区域无提供者、评价、价格、权益、时间、通知、支付或工程术语。

## 浏览器挂载验证

受控浏览器会话使用同一家庭的只读客户投影完成 UI-24 挂载。动态卡状态为 `READY`，仅展示“家庭支持记录”“已经记下的支持需求”“亲子沟通支持”“需求已记下”、过程回看说明和两个内部回看入口。页面挂载记录的动态标记为无外部动作；未显示服务者、资格、评价、价格、权益、时间、通知、支付、订单、真人排期或工程术语。原始服务记录视觉基线保持在动态卡之前。

移动端复核显示，家庭支持记录卡与原始服务记录基线以清晰留白分隔；卡片内的“亲子沟通支持”“需求已记下”与过程说明可读，两个入口保持明确层级和足够间距。动态区域未把原图的服务者、活动、会员或静态时间元素解释为真实服务事实。
