# UI-10 成长小助手行动提示 PDCA 001

> **本轮范围**：把 UI-09 已记录的家庭行动，连接到 UI-10 的成长小助手。页面只提供家庭内、可选择、简短的下一次行动提示；不对孩子作画像、诊断、排名或效果判断，也不调用模型、监测儿童或发布信息。

| 字段 | 本轮定义 |
|---|---|
| `PDCA_ROUND` | `UI09_ACTION_TO_UI10_CHILD_PROMPT_001` |
| `SOURCE_UI` | UI-09（今日家庭行动已记录） |
| `TARGET_UI` | UI-10（成长小助手） |
| `USER_JOURNEY` | 家长记录一次今日行动 → 打开成长小助手 → 与孩子一起选择一个轻松的下一次小行动，或先暂停。 |
| `CHILD_EXPERIENCE` | 有选择、不被评分、不被追踪；提示以“可以试试”而非“必须完成”呈现。 |
| `PARENT_EXPERIENCE` | 获得一个可在日常中共同尝试的小提示，不被要求证明孩子改变或填报孩子表现。 |
| `FAMILY_EXPERIENCE` | 使用可预测但保有选择空间的日常节奏，让亲子互动回到对话和共同决定。 |
| `PERSISTENCE` | 复用 UI-09 成功完成后的家庭内回顾入口事件；本轮不创建儿童档案、积分、勋章、奖励、任务、通知、Outcome 或外部效果。 |
| `FRONTEND_RULE` | 前台不显示 DEV、synthetic、模型网关、审核、证据等级、测试回执、工程命令或内部数据源。 |

## 1. Plan：外部研究与用户需求

儿童自主支持的相关研究将家长的支持行为描述为鼓励孩子在选择、问题解决与兴趣相关行动上保持独立性；积极引导、低控制和及时回应是其设计线索。[1] 这并不支持把系统提示当成对孩子的判断或自动指令。因此，本轮小助手只呈现可拒绝、可替换、可暂停的家庭小行动，不记录孩子是否照做。

美国儿科学会面向家庭的日常惯例建议强调，稳定而可预期的节奏与保有儿童选择空间之间需要平衡；在日常情境中提供可选择的方式，以及避免批评性的对话，可帮助家庭把互动放回自然生活。[2] 这只是本轮内容和交互设计的参考，不是对任何单个家庭或儿童的效果承诺。

| 用户问题 | UI-10 的回答 | 数据边界 |
|---|---|---|
| “孩子能不能参与下一步？” | 用一个简短的共同选择提示，让家庭决定是否尝试。 | 只读提示，不写儿童意愿或能力档案。 |
| “今天已经够累了，还要继续吗？” | 提供“今天先到这里也可以”的暂停说明。 | 不扣分、不记录失败、不发提醒。 |
| “会不会变成积分和排行榜？” | 不增加分数、连续天数、勋章或跨家庭比较。 | 原始基线中的视觉元素不参与动态判断。 |
| “这是 AI 在评价孩子吗？” | 不使用诊断、预测、评价或自由文本模型输出；仅以家庭已记录行动为入口显示规则化提示。 | 无模型调用、无儿童监控、无核心本体写入。 |

## 2. Do：最小实现设计

Core Growth 投影在 UI-10 卡增加 `child_action_prompt`。仅当同一家庭的 UI-09 行动已完成并有回顾入口事件时显示。字段包括：对家庭友好的标题、一项可尝试的小行动、可暂停说明、返回 UI-09 的行动入口以及行动边界。它不包含儿童姓名、年龄、能力、情绪、积分、奖励、完成状态、Outcome 或模型结论。

UI-10 保留原始成长小助手基线图，在基线后追加一张“和孩子一起选一件小事”卡。家长可以点击“回到今天的行动”；暂停说明不产生任何写入。原图中的挑战、奖励或能量视觉结构不被用于动态评分或奖励结算。

## 3. Check：验收原则

测试需要证明：没有 UI-09 行动记录时 UI-10 不伪造提示；同一家庭行动记录才能生成提示；跨家庭不可读；投影不含儿童画像、分数、奖励、排名、Outcome 或模型输出；UI-10 基线保持；行动入口只回到 UI-09；前台无工程术语。移动端复核需确认提示卡不覆盖原图挑战、奖励与底部导航区域。

移动端视觉复核通过：UI-10 原始成长小助手基线图完整保留；共同选择提示卡位于基线下方，不覆盖成长能量、等级、四色活动卡、今日挑战、奖励展示或“开始挑战”主按钮。动态卡只使用“可以一起试试”和“今天先到这里也可以”的非评判性语言，不将能量、星星、奖励或挑战内容带入动态判断；返回今天行动的按钮层级清晰。
