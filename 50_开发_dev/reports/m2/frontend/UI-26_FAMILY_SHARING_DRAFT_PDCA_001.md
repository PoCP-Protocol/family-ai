# UI-26 家庭分享草稿 PDCA 001

## 用户问题与本轮目标

在阅读其他家庭的日常经验之后，家长有时会想把自己正在尝试的一件小事写下来，先留给家庭内部慢慢修改、讨论或暂缓。本轮把 UI-26 定位为**家庭分享草稿**：它帮助家长整理一句愿意保留的日常感受，但不把草稿变为公开动态、也不把文字视为儿童成长结论。

| 用户 | 需要的体验 | 本轮实现 |
|---|---|---|
| 家长 | 能先写下一段家庭想法，而不必马上公开 | 提供受控草稿模板与“先记下”动作 |
| 孩子 | 不因家长记录而被识别、评价或暴露隐私 | 不出现儿童姓名、照片、年龄、学校、标签或效果判断 |
| 家庭 | 能保留决定权，不被分享、互动或传播催促 | 明确“先留给家庭”的文案与返回经验阅读入口 |
| 平台 | 验证经验阅读到家庭表达的血缘，不产生社区副作用 | 只复用受保护草稿记录，不执行发布、媒体、评论、通知或分享 |

## 研究输入与产品判断

Family Voices 的家庭中心叙事指南强调，故事的所有者应理解参与范围、目的和受众，并可随时退出或撤回；匿名或化名有助于保护隐私。[1] 因此，本轮不设计默认发布，也不读取联系人、媒体或公开范围；草稿仅是家庭内部的可修改表达。

美国 FTC 对 COPPA 的规则摘要指出，面向儿童或明知收集 13 岁以下儿童在线个人信息的服务受到专门要求约束。[2] 本轮以更严格的产品选择处理家庭草稿：动态区域不收集或展示儿童识别信息，不上传图片、音视频或位置，也不从草稿推断儿童状态或结果。

> 本轮的“记下分享草稿”仅意味着家庭保留了一段可继续修改的想法；它不代表已发布、已审核、已被他人阅读、已获得互动，或证明任何教育结果。

## 基线与动态内容边界

UI-26 对标 `apps/web/public/bangyang-reference/publish-dynamic-reference-548x1028.png`。原图中的发布类型、素材入口、话题、挑战、可见性和发布按钮均保留为视觉基线。本轮动态草稿卡只追加在原图之后，展示家庭草稿标题、温和的草稿正文、可延后决定提示和回到经验阅读的入口。

| 动态可读/可写内容 | 本轮明确不创建或不展示 |
|---|---|
| 家庭内草稿标题与模板文本 | Post、公开可见范围、作者资料、儿童身份、媒体、话题、挑战 |
| 一次受保护的草稿记录反馈 | 发布、评论、回复、点赞、收藏、分享、下载、通知、举报、审核 |
| 回到 UI-25 经验阅读入口 | 外发、联系人、社交图谱、交易、奖励、效果结论 |

## 数据与流程边界

> UI-25 家庭经验阅读 → UI-26 家庭分享草稿 → 返回 UI-25 家庭经验阅读。

本轮可复用既有受保护体验动作作为家庭内草稿记录；前台只接受成功/失败的中性状态。不会新增正式 `Post`、`Media`、`Visibility`、`Comment` 或 `Reaction` 对象。草稿模板不是对家庭或儿童的事实陈述，也不会进入成长结果、诊断、排名或奖励对象。

## 验收标准

1. UI-25 能进入 UI-26；UI-26 能回到 UI-25。
2. UI-26 只显示家庭草稿与可延后决定提示；不显示作者、儿童信息、公开范围、媒体、话题、互动、分享、审核或交易内容。
3. “记下分享草稿”最多执行一条受保护家庭范围请求；不执行真实发布、媒体上传、联系人读取、通知或外发。
4. 自动化测试覆盖入口、草稿记录、失败态、回流和无发布互动写入。
5. 移动端复核确认动态草稿卡位于原始发布页基线之后，且原图中的发布视觉不构成动态事实。

## Check：移动端视觉复核

在受控本地会话中，从 UI-25 的“写下家庭想法”入口进入 UI-26，并以无外发的受保护草稿响应完成“记下分享草稿”动作。原始发布页基线完整保留；其后的动态卡只显示“家庭分享草稿”“先留给家庭，再慢慢决定”和“这段家庭想法已记下。可以慢慢修改，是否分享由你们之后再决定。”动态区域未提供联系人、照片或媒体上传、公开发布、评论、点赞、通知、支付或外发入口。

> 本轮视觉复核确认的是**家庭内草稿被记下**，不等同于公开分享、发布成功或产生任何外部效果。
