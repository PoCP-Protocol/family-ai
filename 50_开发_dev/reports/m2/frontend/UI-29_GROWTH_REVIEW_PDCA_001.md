# UI-29 成长回顾 PDCA 001

## 用户问题与本轮目标

UI-29 原始页面使用连续打卡天数、成长值、任务完成数、奖章与“前后变化”故事来组织信息。对家长与孩子而言，真正有价值的不是再确认一个分数或给孩子贴上“进步”的结论，而是能温和地回看家庭已做过的一次行动，并决定是否回到计划或把这段过程留成私密故事。

本轮将 UI-29 定位为**家庭成长回顾**。它只显示已记录的家庭行动和一个可反思的过程提示，且保持与 UI-05 成长计划、UI-12 私密成长故事之间的可回退血缘。它不创建 Outcome、孩子画像、排名、总分、奖励、徽章、公开成果或因果性教育结论。

| 用户 | 需要的体验 | 本轮设计 |
|---|---|---|
| 家长 | 回看已经尝试过什么，而不必判断做得好不好 | 用“已经留下一次家庭行动”呈现行动记录，并提供下一步选择。 |
| 孩子 | 不被成绩、比较或成人叙事定义 | 不在动态卡呈现个人表现、前后对比、能力判断、诊断、数值、排名或徽章。 |
| 家庭 | 选择继续、暂停或回看，不被平台催促 | 提供“回到成长计划”与“查看家庭故事”两个可逆入口。 |
| 平台 | 让成长系统保留事实、观点、建议和行动的区分 | 只使用已完成行动作为事实；反思提示是家庭观点邀请，不是结果证据。 |

## 研究输入与设计判断

关于家长反思功能的研究将反思性照料描述为带着好奇心理解亲子互动中想法与感受的能力，并强调父母与孩子的心理状态是彼此独立且有时不透明的；这支持用“我注意到了什么”“下次想怎么试”来邀请回看，而非依据单次记录推出儿童状态或家庭效果。[1]

另一项关于过程与人格导向反馈的研究显示，不同领域和不同反馈方式的作用并不一致，研究者特别指出亲社会领域中过程导向与人格导向反馈的效果存在复杂性。[2] 因此，本轮不把“过程导向”写成保证有效的公式，也不把行动次数、时间跨度或单个故事转译为成长成果；页面只保留行动事实和家庭自主选择。

> UI-29 中“已经留下一次家庭行动”只说明一个受控行动已被记录；它不证明儿童发生改变、家庭获得成果、行动带来因果效果，或故事应被公开。

## 视觉基线与动态内容边界

UI-29 对标 `apps/web/public/bangyang-reference/growth-outcomes-reference-522x1110.png`。基线图为常规可读的 522×1110 纵向页面，不需要分块处理。图中的“成长值”、连续天数、任务比例、荣誉勋章、前后对比、照片与海报按钮仅作为既有视觉基线保留，**不会被动态逻辑读取、计算或解释为事实**。家庭成长回顾卡追加在基线之后。

| 动态可呈现 | 本轮不呈现、不创建或不推断 |
|---|---|
| 家庭行动已记录这一事实 | 成长值、排名、总分、连续天数、任务比例、奖章与奖励 |
| 家庭可自己决定下次如何继续的提示 | 儿童能力、行为归因、诊断、前后比较与教育效果结论 |
| 回到成长计划、查看私密成长故事 | 公开海报、媒体、下载、分享、通知、导出与外部发布 |

## 数据与流程边界

> UI-09 今日行动记录 → UI-08 家庭回顾 → UI-29 成长回顾 → UI-05 成长计划或 UI-12 私密成长故事。

UI-29 从既有核心成长投影读取最近的 UI-09 行动记录；只有已记录的行动可形成“已留下”状态。卡片不回显儿童姓名、反思正文、量化绩效或第三方素材。若尚无记录，则提示先从计划中的一件小行动开始。所有文字只构成阅读引导；不新增写入、确认、纠错、分享、导出或通知动作。

## 验收标准

1. UI-29 可从核心成长投影判断是否存在已经记录的家庭行动；没有记录时显示自然空态。
2. 已记录状态只说明家庭行动被记下，不解释为儿童变化、成果、效果、评分、排名或诊断。
3. UI-29 只提供回到成长计划与查看私密成长故事的页面入口，不发起任何写入或外部调用。
4. 自动化测试覆盖已记录与空态、UI-29 到 UI-05/UI-12 的入口、无网络写入与禁止高风险词。
5. 移动端复核确认动态回顾卡追加在原始成果视觉基线之后，不替换原始布局。

## 视觉复核记录

在本地页面 `http://localhost:5173/?product=test-loop&page=growth-outcomes` 复核基线模式。原始 522×1110 成果页面保持完整，底部热点已改为“查看家庭故事”；动态区域在未启用受控读取时不出现，因此不会把基线中的数值、徽章或前后对比误当作实时家庭数据。

在启用受控读取参数、但未提供本地认证会话时，UI-29 正确显示“这段家庭过程暂时无法回看”与“回到成长计划”的自然回退入口；页面没有降级为本地伪造记录。已记录与空态的可视文案、基线追加位置、两条页面血缘与零写入由 `test-loop.page-objects.spec.ts` 的自动化页面对象测试验证。
