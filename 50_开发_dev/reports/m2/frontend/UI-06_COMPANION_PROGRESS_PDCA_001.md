# UI-06 90 天陪跑进度 PDCA 001

> **本轮范围**：将 UI-09 已记录的家庭行动与 UI-08 家庭成长回顾，连接到 UI-06 的 90 天陪跑进度。页面帮助家长了解“此刻可从哪里继续、要不要先暂停、可回看什么”，而不将过程数量解释为孩子发展结果、家庭分数或服务履约。

| 字段 | 本轮定义 |
|---|---|
| `PDCA_ROUND` | `UI09_UI08_TO_UI06_COMPANION_PROGRESS_001` |
| `SOURCE_UI` | UI-09（行动已记录）、UI-08（家庭成长回顾） |
| `TARGET_UI` | UI-06（陪跑服务） |
| `USER_JOURNEY` | 完成今日行动 → 查看家庭回顾 → 打开陪跑服务 → 看见“本周已记录一件行动”与温和的继续/回看入口。 |
| `CHILD_EXPERIENCE` | 不被完成率或服务标签评价；家庭可以按当天精力和互动情境选择继续或暂停。 |
| `PARENT_EXPERIENCE` | 不必读取抽象百分比；用“一件已记录行动 + 一个可选下一步”理解当前节奏。 |
| `FAMILY_EXPERIENCE` | 将长期计划放回自然日常，而不是把陪跑变成公开打卡或被比较的表现。 |
| `PERSISTENCE` | 复用 UI-09 已完成行动后的家庭内回顾入口事件，不新建 `ServiceCase`、`Booking`、`CommunityPost`、`Notification`、`Outcome` 或外部消息。 |
| `FACT_BOUNDARY` | 事实是“家庭行动已记录”；陪跑提示、回顾问题和下一步都不是教育效果、儿童判断或服务履约。 |
| `FRONTEND_RULE` | 前台不显示 DEV、synthetic、模型网关、审核、证据等级、测试回执或工程命令。 |

## 1. Plan：用户需要、研究与视觉基线

UI-06 视觉基线为 `apps/web/public/bangyang-reference/delivery-community-reference-458x1128.png`，尺寸 458 × 1128px，并按重叠区阅读为两个纵向区域。页面包含“陪跑服务”标题、四张服务支持卡、本周完成度卡、三条过程记录、成长打卡/家长交流/本周直播标签、动态样式内容、浮动打卡按钮和底部导航。服务卡、百分比、动态、互动数和直播文字都是原图的视觉内容；本轮不将其解释为真人在线、已预约、已提醒、已阅读、已发布或真实成效。

家庭日常惯例是家庭支持的自然情境；相关研究强调支持应当在家庭可持续的日常生活中结合家庭的目标、优势、资源和压力来设计。[1] 本轮仅借此作为设计输入：陪跑进度要围绕家庭当前能够承担的一件小行动和下一步选择，而不是要求按固定比例完成。对于回顾，先看见事件、再讨论可能的理解、再想象调整方式的过程适合形成非评判性用户提示；它不能被误用为对儿童或家庭的判断。[2]

| 家长问题 | UI-06 的回答 | 本轮数据边界 |
|---|---|---|
| “今天已经做了一次，接下来怎么办？” | 显示“本周已记录一件家庭行动”，并提供继续今天行动或查看家庭回顾。 | 仅由 UI-09 行动后的回顾入口事件派生。 |
| “没有做到很多，会不会落后？” | 不显示动态完成率、连胜、排名或进度分；强调每个家庭可按自己的节奏继续或暂停。 | 原图数值保持视觉基线，不参与动态判断。 |
| “顾问、提醒、直播是不是已经给我安排好了？” | 不在动态卡中重复或承诺原图服务能力。 | 不创建 ServiceCase、预约、提醒或直播互动。 |
| “我能否把今天放回长期计划？” | 给出查看家庭回顾与继续今天行动的页内入口。 | 导航只读；不自动调整正式计划或任务。 |

## 2. Do：最小实现设计

Core Growth 投影在 UI-06 卡增加 `companion_progress`。只有同一家庭的 UI-09 已成功完成并记录回顾入口后才出现。投影包含关注方向、行动已记录确认、一条节奏提示、UI-08 回顾入口和 UI-09 当日行动入口；不含完成率、服务人员、社区内容、点赞、评论、预约、通知、Outcome 或儿童画像字段。

UI-06 保留原始基线图，并将“本周陪跑”卡追加在基线图后。用户可以选择“查看家庭回顾”或“继续今天的行动”。基线图内的浮动“＋打卡”仍沿用现有 UI-09 路由；本轮不会公开发布动态或触发任何外部服务。

## 3. Check：测试与视觉验收

自动化测试覆盖：UI-06 无 UI-09 记录时不伪造陪跑进度；同一家庭的 UI-09 回顾入口产生 UI-06 投影；跨家庭不可读；投影没有百分比、排名、Outcome、服务预约或通知字段；UI-06 路由保留基线；动态卡不展示工程术语；两个用户入口只切换到 UI-08/UI-09。

视觉验收重点：原图完整保留；动态卡在原图下方；文本不覆盖 2×2 服务卡、过程卡、标签、动态区或导航；内容避免“完成度”“成绩”“表现”“专家已服务”等暗示。

## 4. Act：本轮提交准则

本轮完成研究、实现、自动化测试、移动端视觉复核和修复后，只提交 UI-06 纵切相关的文档、共享契约、服务、控制器、前端、样式和测试。推送完成前不开始 UI-07、UI-10 或其它服务/社区/交易页面，也不提交两份既有 UI-06 旧草稿或 PPT 分析资产。
