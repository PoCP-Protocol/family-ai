# UI-18 家庭服务范围与计划入口 PDCA 001

## 1. 本轮范围

UI-18 当前路由为“我的”服务与会员视觉页。原始页面包含头像、静态成长数字、等级、功能菜单及年度会员服务卡。**本轮不把这些视觉数字解释为家庭成长评价、积分、服务履约、权益事实或有效期承诺。**本轮只在原图之后接入同一家庭可读的服务范围投影：家庭已经拥有的测试服务计划名称、可查看的支持项目，以及返回家庭成长计划的入口。

| 项目 | 本轮决定 |
|---|---|
| 用户目标 | 家长能知道“这项家庭服务可以怎样支持我们”，并回到自己的成长计划继续安排。 |
| 读取对象 | `MembershipCustomerProjection` 的家庭私有订阅与可用支持项目摘要。 |
| 不读取为前台事实 | 静态等级、成长积分、邀请人数、提现、奖励、优惠、到期日期及销售文案。 |
| 不执行动作 | 续费、退款、购买、权益授予或消耗、客服建单、通知、联系人读取、外部发送。 |
| 入口与回流 | UI-18 服务范围卡 → UI-05 90 天成长计划；可返回 UI-07 成长档案。 |

## 2. 视觉基线与身份对账

已读取 `apps/web/public/bangyang-reference/ui18/commerce-06-mine-member.png`（244×545）。页面含“我的”顶部区、静态数字、等级菜单、年度会员服务卡及底部导航。它可以保留作为视觉基线，但其中的数字、会员称谓与到期展示缺少本轮动态事实来源，因此不用于动态判断。

工程内已有会员计划、订阅、权益授予和家庭私有客户投影的测试支撑。其读取端点为：

```text
GET /families/{familyId}/orchestration/test-loop/membership/customer-projection
```

该读取投影具有家庭范围与私有可见性，适合本轮展示“家庭已可查看的支持项目”。但建立订阅、权益授予、消耗、撤销仍归属其他业务页面和受保护动作，不能由 UI-18 触发。

## 3. 用户需求与研究输入

家长需要的不是被等级、积分或续费压力驱动，而是清楚知道哪些支持可供家庭了解、为什么相关、下一步可以返回哪一份家庭计划。孩子不应被会员层级、权益数量或服务使用次数评价。

Family Voices 将家庭中心服务描述为尊重家庭优势、文化与专业经验的伙伴关系，并强调向家庭提供诚实、无偏且可用的信息，以及支持家庭对支持方式作出选择。[1] Head Start 将家庭参与描述为建立在相互尊重、优势取向和共同目标关系上的持续伙伴关系。[2] 因此，本轮将 UI-18 的动态体验收敛为：**透明说明、家庭自主、可返回计划，不作等级或消费驱动。**

## 4. 最小对象关系与读模型

```text
Family
  └─ MembershipCustomerProjection (FAMILY_PRIVATE, 只读)
       ├─ SubscriptionSummary (计划名称、当前可读状态)
       └─ BenefitSummary[] (支持项目标题、可查看状态)

UI-18 FamilyServiceScopeProjection
  ├─ headline
  ├─ summary
  ├─ support_items[]
  ├─ plan_route = core-plan
  ├─ profile_route = core-mine
  └─ boundary = READ_ONLY_NO_RENEWAL_NO_REFUND_NO_GRANT_NO_CONSUME
```

`MembershipCustomerProjection` 是现有的家族范围读取输入；UI-18 前端将把它转换为家庭可理解的 `FamilyServiceScopeProjection`。这不是新的会员、权益或订单事实，也不会建立平行账本。

## 5. 前端状态与用户文案

| 状态 | 用户看到的内容 | 禁止内容 |
|---|---|---|
| 加载中 | “正在准备家庭服务说明…” | 读取来源、接口、测试或内部状态术语。 |
| 可读 | “可以从这些支持中慢慢了解，按家庭节奏选择。” | 等级、积分、优惠、续费倒计时、效果承诺。 |
| 无可读项目 | “现在还没有需要安排的服务内容，可以先继续家庭成长计划。” | 诱导购买或服务缺失归责。 |
| 暂不可读 | “家庭服务说明暂时无法加载，请稍后再试。” | 本地伪造权益或失败原因细节。 |

## 6. 实现边界与验收

本轮实现将复用现有家族范围 `GET` 读取；只在 UI-18 页面启用，并且保持 UI-30 的订阅、UI-31 的权益消耗、UI-32 的资产或撤销动作不变。自动化验收须验证家族范围、无读写混淆、空态、无跨家庭数据，以及前台不出现积分、奖励、价格、支付、订单、续费、退款、权益数量、工程术语或儿童评价。视觉验收须验证动态卡位于基线图之后。

## 8. 浏览器视觉复核

在 `commerce-mine` 路由挂载家庭私有服务范围测试投影后，原始会员中心基线图保持完整可见；家庭服务说明卡位于其后，以“家庭交流支持”“成长内容支持”及“查看成长档案”“查看成长计划”呈现。动态区域未出现等级、积分、额度、到期、续费、退款、支付、订单或权益账本信息，也未覆盖原始卡片和底部导航。

本轮视觉结论为：**通过。**动态内容与原图静态会员视觉保持明确分隔，用户可理解其为家庭支持说明，而不是对家庭或孩子的等级、消费或成长判断。

按钮区复核显示“查看成长档案”与“查看成长计划”以并列主次操作呈现，按钮间距和触控区域清晰；卡片仍与会员中心基线保持视觉分隔，不遮挡静态会员服务卡和底部导航。

## 10. PDCA 本轮结论

**Plan**：将 UI-18 从会员数字视觉改为可理解的家庭服务范围说明。**Do**：接入家庭范围会员客户投影的只读读取，并将支持项目转为中性服务说明及成长计划/档案入口。**Check**：完成定向、集成、全量自动化测试及移动端视觉复核。**Act**：保留订阅、授予、消耗和撤销能力在既有受保护页面和服务中；UI-18 仅承担家庭服务说明的阅读与回流。
