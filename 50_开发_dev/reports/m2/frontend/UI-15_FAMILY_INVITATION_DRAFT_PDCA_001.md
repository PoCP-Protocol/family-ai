# UI-15 家庭邀请说明草稿 PDCA 001

## 1. 本轮范围

本轮从 UI-14 内容详情进入 UI-15 邀请页面。目标不是发出邀请、收集联系人或发放奖励，而是让家长把“是否愿意向熟悉家庭介绍这项内容”的想法先整理成一份家庭内说明草稿，之后再自行决定是否采取下一步。

| 项目 | 本轮实现 | 明确不做 |
|---|---|---|
| 用户路径 | UI-14 内容详情 → UI-15 邀请说明草稿 → 回到内容详情 | 联系人读取、通讯录权限、复制、外发、分享、二维码生成、通知、奖励发放、权益变更、支付 |
| 数据关系 | UI-14 已选目录条目的引用传入 UI-15；复用已有家庭范围的测试邀请操作 | 将静态邀请码、人数、奖励、优惠、邀请码、二维码或分享方式转化为动态事实 |
| 用户表达 | “准备一段邀请说明”“是否发送由你们决定”“可以之后再决定” | “立即邀请”“邀请即得”“再邀几人”“奖励到账”“解锁权益” |
| 视觉策略 | 完整保留 UI-15 原图，在原图之后追加轻量草稿卡 | 重绘原图邀请进度、奖励、邀请码、二维码或分享方式视觉 |

## 2. 用户需求与设计依据

家庭是否向他人介绍一项成长内容，应由家长自主决定，并有机会在理解内容、考虑隐私和关系边界后再行动。家长参与相关说明强调，知情同意以家长已获得与活动相关的信息为前提。[1] 家庭中心实践则主张提供完整、尽量中性的资料，让家庭据此作出自己的决定。[2] 本轮只把这两点作为界面设计输入：用家庭内说明草稿替代默认外发、奖励诱导或社交压力；不对邀请行为、奖励、公平性、转化或家庭成长结果作任何承诺。

> “Consent … means that you, as parents, have been fully informed of all information that's relevant to the activity for which your consent is being sought.” — Center for Parent Information and Resources.[1]

## 3. 基线阅读与保真边界

UI-15 基线图为 `commerce-03-invite.png`，尺寸为 240 × 545 像素。可见结构包括“邀请有礼”横幅、静态的 1/3 邀请进度、奖励卡、立即邀请、微信/朋友圈/生成海报入口及二维码。本轮完整保留原图。其静态人数、奖励、优惠、邀请码、二维码、分享渠道和按钮不读取、不解释、不作为动态草稿输入，也不触发任何外发或权益动作。

动态卡固定追加在原图之后，只显示“家庭邀请说明”、当前内容标题、可延后决定说明、记下草稿和回到内容详情两个入口。动态层不显示真实被邀请家庭、联系方式、邀请码、二维码、奖励、优惠、权益、通知、分享记录或订单状态。

## 4. 数据与行动边界

```text
UI-14 selected catalog item
  └─ { product_ref, product_version, title }
       └─ UI-15 invitation explanation draft
            └─ existing protected DEV/TEST invitation-draft operation
                 └─ family-scoped operation receipt; no external effect
```

受保护邀请操作在测试环境下记录家庭范围的草稿与幂等审计信息。前台只显示“邀请说明已记下”，不显示操作名称、环境、审计字段、回执编号或适配器状态。草稿不代表联系人访问、邀请发送、对方接收、二维码生成、奖励计算、权益发放、订单确认、支付或服务履约。

## 5. 验收标准

1. UI-14 的“准备一段邀请说明”入口进入 UI-15；已选目录条目保持一致。
2. UI-15 动态草稿卡只显示当前内容标题、家庭自主决定说明和两个入口。
3. 记下草稿仅调用既有受保护的 UI-15 测试邀请操作；响应必须保持 `external_effect=false`。
4. 动态前台不显示 DEV、synthetic、no-op、模型、审计、内部状态、真实对象、邀请码、二维码、奖励、价格、优惠、权益、订单、支付、外发、通知或分享术语。
5. UI-15 原图保持完整；动态内容位于原图之后。
6. 完成聚焦 API/前端测试、API 与 Web 全量回归、浏览器视觉复核，然后仅提交本轮文档与相关程序。

## 6. 浏览器复核准备

已在刷新后的本地会话挂载同一家庭的目录条目，再从 UI-14 内容详情进入 UI-15 并触发“记下邀请说明”。测试响应仅为家庭范围草稿，状态为 `CREATED` 且 `external_effect=false`。接下来以实际移动端渲染检查原始邀请图与动态说明卡的层级、可读性及前台文案。

## 7. 移动端视觉复核

移动端复核确认：UI-15 原始邀请基线图完整保留；家庭邀请说明卡位于原图之后，清楚显示当前内容“亲子沟通小练习”和“邀请说明已记下”。动态区域仅提供“记下邀请说明”和“回到内容详情”。它不显示真实被邀请家庭、联系方式、邀请码、二维码、奖励、优惠、权益、订单、支付、邀请发送、通知、分享、下载、发布或工程过程信息。原图中的静态进度、奖励、二维码和分享方式保持为未改动的视觉基线，未被读取、解释或写入。
