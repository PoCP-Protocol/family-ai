## 单页验收固定步骤

| 步骤 | 必须产物 | 未满足时的处理 |
|---|---|---|
| 1. 原图登记 | 文件名、像素、可见元素、页面 ID。 | 不开始实现。 |
| 2. 元素规格 | 结构、文字、尺寸、颜色、图标、插画、状态、交互热点。 | 不使用“相近”替代。 |
| 3. 资产确认 | 原始插画/图标/人物卡来源，或用户确认可用的逐像素页面视觉母版。 | 不自行创作最终视觉资产。 |
| 4. 页面实现 | 有真实可点击热点或受控页面路由。 | 不让互动覆盖改变可见原图。 |
| 5. 浏览器截图 | 同宽高截图与原图并列。 | 记录每个可见差异。 |
| 6. 差异修正 | 逐项关闭尺寸、排版、图标、插画、颜色、留白、状态差异。 | 任一差异未闭环即 `NOT_MATCHED`。 |

## 当前阻断与执行顺序

当前仅首页 B01 和家庭测评第 2/5 步拥有单页清晰图。首页视觉母版已被保存为本地开发参考并叠加透明交互热点，但该方法只能证明**页面视觉对照**，不能替代后续可编辑组件、真实数据或生产能力。家庭测评第 2/5 步仍需持续精确校准。其余 16 页应依用户逐张提供的清晰原图排序进入，不以组合图低清预览作为最终验收依据。

## PPT 联系表复核发现

完整 PPT 的前八页联系表确认了两套关键 App 页面母版：第 5 页为“小程序 UI 方案参考”，第 6 页为“增长优化场景 UI 设计补充”，第 8 页为“分享裂变商城方案”。这些页面分别承载商城/分享组、增长优化组和综合家庭首页的 18 页 UI 线索。联系表适合确认页面分组、图标色彩、顶部导航和流程关系，但单个手机画面在联系表中分辨率不足，不能替代单页清晰原图的最终验收作用。

后续顺序仍保持：先完成已有清晰首页和家庭测评第 2/5 步的逐像素对照；再将 PPT 第 5、6、8 页中的六机位 UI 按页面拆出为独立清晰参考，并逐页建立元素规格。任何无法从拆出图读清的文字、图标或插画，均继续标记 `NEEDS_CLEAR_REFERENCE`。

## 第 5 页高分辨率 UI 方案：已确认的六页顺序

PPT 第 5 页以清晰的六机位顺序给出：`1 首页`、`2 家庭测评`、`3 AI诊断报告`、`4 个性化成长方案`、`5 陪跑交付 / 社群服务`、`6 我的 / 会员中心`。该页确认首页和家庭测评对应用户已单独提供的两张清晰图；其余四页的原图布局可由本页高分辨率预览先行提取，并在获得单页清晰图后再做最终验收。

可见共同视觉规则是：白色手机框、深蓝黑标题、亮蓝主按钮、橙色阶段 CTA、极浅灰蓝背景、圆角白色模块、彩色语义标签、固定四栏 tab bar。页面 3 使用儿童信息蓝卡、中心雷达图和“生成个性化方案”主按钮；页面 4 使用橙色阶段首屏、3/12/36/90 时间节点、纵向周计划和“开始执行计划”按钮；页面 5 使用顶部家庭顾问/班主任卡、进度条、阶段任务、底部社群动态；页面 6 使用深蓝会员卡、邀请奖励、功能菜单和深色年度会员 Banner。

## 第 6 页高分辨率增长优化 UI：已确认的六页顺序

PPT 第 6 页给出：`1 家庭成长体检入口`、`2 AI体检报告`、`3 每日任务 / AI管家`、`4 孩子端成长助手`、`5 家庭成长排行榜`、`6 成长报告海报 / 一键分享`。页面 1 使用蓝色大测评 Banner、五维快捷卡与示例问题；页面 2 使用儿童信息蓝卡、六维雷达图、优势/风险/优先建议行与 7/30/90 路径；页面 3 使用机器人蓝色提示 Banner、三项编号任务、周完成度和打卡天数；页面 4 使用浅蓝儿童 Hero、成长能量条、四色成长卡、今日挑战与奖励；页面 5 使用四分段筛选栏、前三名台座、列表与个人排名卡；页面 6 使用亮蓝成果海报、前后变化卡、连续打卡/成长值、奖章、二维码和三项分享动作。

## 第 8 页高分辨率分享裂变商城 UI：已确认的六页顺序

PPT 第 8 页给出：`1 裂变商城首页`、`2 商品详情`、`3 邀请有礼`、`4 拼团专区`、`5 积分商城 / 任务中心`、`6 我的收益 / 会员中心`。其视觉规律是白底小程序框架、亮蓝邀请/积分大卡、彩色 3×2 快捷功能图标、橙色拼团 CTA、商品/工具包横向卡、任务列表和深色会员权益 Banner。该页是商城/分享组的高分辨率组合原图来源。

当前 Family DEV 的商城、拼团、积分和会员页面仅有功能壳，不能据此被认定为视觉通过。由于现阶段支付、会员权益、真实交易、真实邀请外发、Enrollment/Delivery 和商业化仍 HOLD，复刻时只实现原图可见 UI 与内部合成点击路径；不得接入真实商业交易能力。
