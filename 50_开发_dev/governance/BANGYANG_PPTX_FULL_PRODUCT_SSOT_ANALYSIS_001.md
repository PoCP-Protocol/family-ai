## 1. 原始产品命题

PPT 的终局不是单卖课程，而是由家庭成长入口、智能分发、服务体验、长期陪伴和生态关系组成的“父母成长平台”。其固定叙事顺序为：**孩子问题是入口 → 父母成长是价值 → 家庭改变是结果**。产品实施必须保留这一顺序，不能将 App 收缩成技术工具、单一咨询后台或泛化的 SaaS。

| PPT 页 | 原始命题 | DEV 复刻含义 |
|---:|---|---|
| 1 | 从重投流卖课程升级为经营家庭成长的平台。 | 首页与产品导航以“家庭成长平台”而非技术演示为首要身份。 |
| 2 | 从一次成交转为持续成长的家庭关系。 | “首页—计划—内容—服务—我的”必须形成长期路径。 |
| 3 | 商业模式内核图。 | 作为完整平台的功能域总览：入口、分发、计划、内容、服务、关系、会员。 |
| 4 | 拼多多、字节、海底捞、教育行业能力组合。 | 页面要同时呈现分享/拼团、理解/报告、服务陪伴、21/90 天行动四类体验。 |
| 5 | 小程序 UI 方案。 | 对应家庭成长首页、体检/报告、计划/服务、会员中心等第一组 App 页面。 |
| 6 | 增长优化 UI。 | 对应体检、报告、每日任务、孩子端、榜单、海报第二组页面。 |
| 7 | 家长从孩子问题进入，在父母成长中完成价值交付。 | App 主流程以“入口—理解—行动—改变—长期—传播”呈现。 |
| 8 | 分享裂变商城 UI。 | 对应商城首页、商品详情、邀请、拼团、积分、会员中心第三组页面。 |
| 9 | 成长分享而非硬推销。 | 分享、邀请、拼团、积分、会员在视觉流中保留原位。 |
| 10–15 | 咨询沙龙、社区、客户后台与服务闭环。 | App 还要有服务、社区、活动、记录、订单/权益与“我的”页面壳。 |
| 16–19 | 五级增长、三类产品五类收入、三年路线、用户资产仪表盘。 | 说明页面组是完整平台，而非孤立活动页；先实现首页/会员/社区/我的等基础信息架构。 |
| 20 | 成熟课程、案例和服务能力升级为连接百万家庭的平台。 | 全部页面围绕家庭账户与长期成长旅程串联。 |

## 3. 用户路径与页面状态

| 原始阶段 | 家长心态 | 原始平台动作 | 原始页面/组件 | 当前 DEV 应复刻的状态 |
|---|---|---|---|---|
| 触发 | 孩子出现现实问题 | 内容、沙龙、家庭测评入口 | 首页 Banner、体检入口、内容卡 | `home → assessment` |
| 觉醒 | 想理解原因 | AI 诊断、父母成长报告 | 体检问卷、报告雷达/结论页 | `assessment → report` |
| 行动 | 愿意尝试改变 | 21 天挑战、每日任务 | 任务清单、打卡、进度 | `report → daily-task → plan` |
| 改变 | 希望获得陪伴 | 90 天计划、顾问、社群 | 计划阶段、服务入口、社区 | `plan → service/community` |
| 长期 | 持续支持 | 会员、档案、活动、AI 管家 | 会员中心、我的、成长记录、助手 | `mine/member → record/assistant` |
| 传播 | 分享成长成果 | 报告、邀请、拼团、权益 | 海报、邀请、拼团、积分 | `report → share/invite/group-buy` |

## 4. 贝壳式分配模式的唯一嵌入点

用户指定的贝壳式分配模式只作为原始 PPT “智能分发/内容与服务推荐/服务闭环”的实现补充，不能重排或替换原有产品结构。其表现形态必须是原图风格的**家庭成长路径卡**：在体检报告后、成长计划前，以并列的课程、任务、工具包、活动和陪伴服务卡承接；在计划、会员和客户后台中作为“下一步/为你准备”的内容组再次出现。它不单独成为一个技术后台、算法页或用户可见的治理页面。

| 原始节点 | 贝壳式分配的呈现 | 页面视觉位置 |
|---|---|---|
| 体检报告后 | “为你准备的成长路径”三到四张卡：课程、任务、工具、陪伴。 | 雷达图/阶段路径下方，亮蓝主按钮之前。 |
| 每日任务 | “今天可以继续的成长行动”。 | 任务完成度与底部按钮之间。 |
| 90 天计划 | “下一阶段成长建议”。 | 阶段卡后、服务入口前。 |
| 我的/会员中心 | “为家庭准备的服务与权益”。 | 计划/报告/订单卡之间。 |

## 5. 视觉系统：从原始 PPT 精确抽取

| 视觉项 | 原始测量/规则 | 前端执行要求 |
|---|---|---|
| 主背景 | `#F4F8FF` 约 41.6%，`#FFFFFF` 约 36.7%。 | 冷白/浅灰蓝作为绝大多数画面底色。 |
| 深色 | `#09295A` 约 11.3%，`#0E397A` 次级。 | 深蓝用于标题、深色会员卡、Hero 渐变起点。 |
| 浅蓝 | `#EAF2FF` 约 9.0%，`#D7E8FF` 辅助。 | 资料卡、分区、卡片背景、进度底色。 |
| 强调 | `#FF7A21`、`#FFD77A`。 | 价格/拼团行动、金皇冠、奖章和奖励。 |
| 字体 | 标题 Calibri Light，正文字体 Calibri。 | Web 首选对应字体及同样的轻重、字距与紧凑视觉。 |
| 卡片 | 12–16 px 圆角、细灰蓝边、轻阴影。 | 保持小程序式高信息密度，避免宽桌面卡/大面积留白。 |
| 行动 | 满宽亮蓝胶囊按钮或蓝橙双按钮。 | 页面底部主操作遵循原图位置与比例。 |
| 图标 | 扁平高饱和蓝/绿/橙/黄/紫。 | 分类、奖励、积分和孩子成长用对应色彩角色。 |

## 6. 不得偏离的前端原则

用户可见界面不出现开发、环境、测试、模型、治理、策略、契约、审计、证据、占位或任何内部术语。不得把原图重绘为通用 SaaS、技术控制台、桌面式双栏后台或独立聊天工具。所有新增页面先忠实复刻原图的信息密度、圆角、顶栏、主卡、图标、按钮和 tab bar，再考虑任何后续创新。
