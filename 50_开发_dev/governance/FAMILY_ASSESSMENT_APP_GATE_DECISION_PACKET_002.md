# Family 家庭支持需要与服务偏好确认：Assessment App Gate 裁决包 002

> **状态：`DRAFT_FOR_ASSESSMENT_APP_GATE_DECISION_INPUT`。**
>
> 本版依据总架构师的协作提醒重写：Family 不做“家庭测评得分”，而是分层处理**家庭支持需要与服务偏好确认**。本文不授权业务代码、DTO/API/数据库、问卷运行时、AI 诊断、儿童端、真人转介、危机处理、外部模型、训练、试点、生产或 master 合入。

## 1. 不可改变的定义与硬边界

Family 的入口问题是“这个家庭此刻希望获得什么支持、愿意采用什么服务方式、是否选择下一步”，不是“孩子能力如何”“家庭好不好”或“AI 判断出什么风险”。

| Family 永久禁止（直到独立明确授权） | 说明 |
|---|---|
| Family Total Score、家庭 Ranking、儿童成长分 | 不把家庭或儿童转化为可比较、可竞争、可营销的分数。 |
| AI 诊断、心理健康结论、风险预测 | 不把自填、行为、模型或 E1 材料上升为专业判断。 |
| 永久标签、公开画像、跨家庭比较 | 不创建不可撤回身份结论、公开传播或群体排序。 |
| 复制受版权保护量表题项/算法/报告 | 任何标准化工具须经正版授权与独立 Gate。 |
| E1 材料/主观回访作为效果证据 | 自家材料只能证明来源；主观感受只是服务过程输入，不能证明教育效果。 |
| 自动真人转介、自动危机处置、自动外发 | 无 Human Gate、责任主体与本地协议时一律 fail-closed。 |

## 2. 四层评估/确认体系

| 层级 | 重新定义 | 服务目的 | 数据与输出上限 | 当前状态 |
|---|---|---|---|---|
| **L0** | 入门服务偏好 / 当下需要确认 | 让家长说明当前关切、想先获得的支持以及是否暂不行动 | Need、Intent、家庭选择或 NO_ACTION；无分数、无标签 | **首批唯一候选** |
| **L1** | 家庭共同决策 / 支持目标确认 | 让家庭把已确认的支持方向变成可撤回、可暂停的服务目标 | 家庭自身确认的优先事项、Plan 目标说明；无儿童/家庭标签 | **仅设计候选，需随 L0 或独立 Gate 裁决** |
| **L2** | 标准化筛查工具 | 使用成熟工具识别是否需要进一步了解或专业评估 | 仅工具规定的结果与“建议进一步了解”；不作诊断 | **HOLD；每个工具独立 App Gate** |
| **L3** | 危机 / 安全筛查 | 在安全议题中停止自动产品化流程，进入人工/本地资源路径 | 安全停止事实和人工处理状态；不生成风险评分 | **HOLD；不得作为普通产品评分题** |

## 3. L0：入门服务偏好 / 当下需要确认

### 3.1 页面与用户任务

| 页面步骤 | 家长任务 | 文本体验 | 系统写入上限 |
|---|---|---|---|
| 说明页 | 决定是否开始 | “这不是诊断或给孩子打分。你可以跳过或随时退出。” | 无，直到家庭主动继续。 |
| 当下需要 | 说明此刻最希望理清的事 | “你现在最希望家庭获得哪类支持？” | Need。 |
| 支持偏好 | 选择支持方向 | “你想先从沟通、日常节奏、学习安排，还是暂不行动开始？” | Intent 或 NO_ACTION。 |
| 候选说明 | 决定是否查看安全候选 | “平台只会显示当前已准入且适合此服务边界的选择。” | 无。 |
| 家庭决定 | 选择、拒绝、暂停 | “下一步由你决定，也可以暂不行动。” | Decision；仅 T2 合格后再进入 Plan/Case。 |

### 3.2 L0 的具体约束

| 控制项 | 要求 |
|---|---|
| 授权状态 | 仅作为 `DRAFT_FOR_APP_GATE_DECISION_INPUT` 候选，尚未获实现授权。 |
| 证据等级 | UI/PPT 等自家材料仅为 E1 产品体验输入；不证明效果。 |
| 适用人群 | 当前家庭中的可信监护人；child subject 仅由服务端家庭范围派生。 |
| Consent | 仅在有效 SERVICE consent 与明确文本说明下；可跳过、可退出、可撤回。 |
| Human Gate | 不需要专业判断；一旦出现诊断、危机、真人、外部资源或异常内容，停止自动流程。 |
| 文本等价 | 无图片、音频、视频、色彩、动效、模型时完整可读可完成。 |
| fail-closed | 无可信会话、disabled account、ambiguous context、无 consent、资源未准入、NO_ACTION 伪装为执行、T2 不合格、幂等冲突均拒绝/空状态。 |

### 3.3 L0 不能做的事情

L0 不采集标准量表题项，不显示雷达图/综合分，不输出“优势/风险/问题”，不设连续打卡、奖励、积分、排行榜、儿童任务、AI 结论、真人服务入口、商城或会员转化。

## 4. L1：家庭共同决策 / 支持目标确认

L1 的角色不是评估孩子，而是把家庭已经表达的需要转化为**家庭自己确认的服务目标与边界**。它可以依附于 L0 之后，也可以在既有 Need/Intent 的基础上进入。

| 维度 | L1 允许的表达 | L1 禁止的表达 |
|---|---|---|
| 目标 | “本周希望尝试一次更平和的沟通。” | “提升孩子沟通能力 30%。” |
| 优先级 | “家庭决定先处理晚间作息的沟通。” | “系统判定这是最关键缺陷。” |
| 计划 | “选择一个已准入的下一步；可暂停。” | “必须连续完成 90 天才有效。” |
| 回顾 | “家庭觉得这一步是否有帮助。” | “证明家庭/儿童成长结果。” |
| 数据 | 家庭明确选择、Plan/Case 事实、主观 FollowUp | 画像、长期评分、跨家庭表现比较。 |

| 控制项 | L1 要求 |
|---|---|
| 授权状态 | 仅设计候选，须与 L0 一起或单独进入 App Gate。 |
| 证据等级 | 家庭自身确认；非效果证据。 |
| 适用人群 | 当前家庭的可信监护人；不代替儿童声音、学校或第三方。 |
| Consent | 有效 SERVICE consent；家庭可随时暂停、修改或 NO_ACTION。 |
| Human Gate | 目标涉及危机、专业评估、第三方或真人交付时停止。 |
| 文本等价 | 目标/计划/暂停/退出均有纯文本表达。 |
| fail-closed | 未明确家庭决定、资源未准入、PRACTICE 无 executor、T2 不通过时不创建执行事实。 |

## 5. L2：标准化筛查工具（严格 HOLD）

ASQ、ASQ:SE-2、PSI、PSS 等属于用途、版权、适龄和解释条件不同的工具，不可混用，更不可被改写为“Family 通用成长诊断”。

| 工具类别 | 示例 | 可能用途上限 | 适用人群/条件 | 独立准入要求 |
|---|---|---|---|---|
| 儿童发展/社会情绪筛查 | ASQ-3、ASQ:SE-2 | 是否值得进一步了解/评估 | 明确年龄范围、家长共同审阅 | 正版授权、正式版本、语言/文化适配、培训、计分解释、私密回访与转介网络。 |
| 家长压力 | PSI、PSS | 讨论养育压力与需要支持的方面 | 明确工具适用年龄/人群 | 版权/许可、解释资格、危机边界、禁止用于评级/定价/营销。 |
| 家庭功能/参与 | Family-Centered Care Assessment 等 | 了解家庭对服务参与和支持的感受 | 以工具原始适用范围为准 | 正版授权、用途限定、人工解释、结果最小化。 |
| 亲子互动观察 | NCAST-PCI、PICCOLO | 受训人员观察互动支持点 | 必须由受训人员开展 | 培训、复训、监督、专业责任与服务协议。 |

| L2 不可跳过项 | 说明 |
|---|---|
| 授权状态 | 每一工具单独列出正版授权/费用/使用权、版本、是否允许数字化、中文本地化状态。 |
| 证据等级 | 工具自身的效度/信度、用途、适用人群和局限必须独立证据审查；E1 不可替代。 |
| 适用人群 | 年龄、语言、文化、照护场景、排除条件必须明确。 |
| Human Gate | 受训人员/合格专业人员的解释、复核、转介和争议处理责任必须明确。 |
| 撤回/跳过 | 家庭可拒答、终止；未发生的后续处理可撤回；不因此剥夺基本服务。 |
| 文本等价 | 工具许可允许的文本路径、无障碍和语言支持；不能以图像/AI 强制补答。 |
| fail-closed | 许可、版本、适龄、培训、转介、危机协议、同意或解释责任任一缺失，工具不得呈现或计分。 |

## 6. L3：危机 / 安全筛查（严格 HOLD）

L3 不属于获客漏斗、家庭评分或成长报告。其唯一角色是在潜在安全议题出现时，停止普通自动化服务，把处理交给经授权的人工与本地资源体系。

| L3 要求 | 设计边界 |
|---|---|
| 授权状态 | HOLD；当前无人工责任、本地资源或危机协议，不得实施。 |
| 数据最小化 | 不收集超过安全必要范围的信息；不用于画像、营销、训练或跨家庭分析。 |
| Human Gate | 明确值班/责任主体、升级路径、时限、记录与争议处理。 |
| 跳过/撤回 | 以安全为先，明确哪些处理可撤回、哪些法定/安全限制需提前说明。 |
| 文本等价 | 私密、简洁、非评判文本；不使用红色高分、危机标签或公开提示。 |
| fail-closed | 无本地资源、无人工责任、无法安全存储/传递信息时，普通产品流程不得假装提供危机服务。 |

## 7. 全层通用的数据、证据与用途限制

| 规则 | 全层要求 |
|---|---|
| 家庭所有权 | 任何记录受 family scope 约束，服务端派生 actor/subject/family。 |
| 用途限制 | 仅为当前家庭的确认、服务规划或未来合格的专业处理；不训练、不自学习。 |
| 禁止再利用 | 禁止跨家庭比较、推荐、榜单、分享、公开画像、会员分层、支付定价、商品/服务营销。 |
| 证据分级 | E1 自家 PPT/内容仅可表达体验/内容来源；不自证测评效度、教育效果、治理充分性或专业结论。 |
| 回访语义 | FollowUp 是家庭主观服务感受，不能成为结果分数、模型标签或证据升级。 |
| 退出 | 可跳过、可暂停、可撤回 consent；撤回后 Context Reuse 默认空投影。 |

## 8. Assessment App Gate 的裁决问题

1. 是否确认 App/小程序入口统一使用“家庭支持需要与服务偏好确认”，禁止“AI 成长诊断/家庭测评分/儿童成长分”等命名和语义？
2. 是否只放行 L0 进入下一轮**任务契约设计**，并确认 L0 不使用标准化量表、评分、画像、报告或儿童端？
3. 是否允许 L1 作为 L0 后的家庭共同决策/支持目标确认候选，但只能产生家庭自己确认的服务规划事实？
4. 是否确认 L2 每一个工具独立走授权、证据、适龄、语言、培训、专业解释、转介、隐私与 Human Gate，且在此之前不接入、不得复制题项？
5. 是否确认 L3 在人工责任、危机协议和本地资源未建立前继续完全 HOLD，且不得嵌入普通产品评分/转化流程？
6. 是否确认任何层均禁止总分、排名、成长分、AI 诊断、心理结论、永久标签、公开画像、跨家庭比较和商业化再利用？
7. 是否确认 E1 材料与主观回访永远不得作为工具效度、教育效果或治理放行的证据？
8. 是否确认即便 L0/L1 获准设计，仍需单独 App 实现 Gate 才能改动页面、DTO/API、数据库或浏览器/移动体验？
