# Family 家庭支持评估 Assessment App Gate 裁决包 001

> **状态：`DRAFT_FOR_ASSESSMENT_APP_GATE_DECISION_INPUT`。**
>
> 本包请求总架构师裁决“家庭支持评估”在 App-first 路线中的正确定位、首阶段范围和未来专业工具引入前置条件。它不授权问卷运行时、AI 诊断、评分、画像、真人转介、外部模型、儿童端、支付、试点、生产或 master 合入。

## 1. 为什么测评必须成为入口，但不能成为“AI 诊断”

用户提供的 App/小程序蓝图把“家庭测评/家庭体检”放在首页入口，随后连接报告、方案、任务与陪跑。这个产品逻辑是合理的：家庭通常先需要弄清“此刻最想获得什么帮助”，再选择支持方式。

但把这个入口直接做成“AI 诊断报告、雷达图、成长分数”会同时带来四类风险：把自填信息误作客观结论；将筛查误作诊断；在没有人工责任和转介协议时暴露敏感信号；将儿童与家庭数据沉淀为画像、模型训练或商业分层。

> **拟议原则：Family 的第一层是“家庭支持评估”，服务于家庭选择；不是对孩子、父母或家庭质量打分。**

## 2. 请求裁决的分层范围

| 层级 | 名称 | 能力描述 | 建议状态 |
|---|---|---|---|
| L0 | 家庭需要与偏好确认 | 家长以可跳过文本说明当前关切、支持方向和是否查看合格候选；输出 Need / Intent / NO_ACTION。 | **可作为首阶段 Assessment App Gate 唯一候选。** |
| L1 | 受控筛查 | 采用版权、适龄、语言和专业解释均已明确的成熟筛查工具；输出仅为“建议进一步了解”。 | HOLD，需独立工具许可与专业责任 Gate。 |
| L2 | 专业观察/综合评估 | 由受训人员进行观察、解释、支持计划或转介。 | HOLD，需真人服务、组织访问与专业责任 Gate。 |
| L3 | 安全/危机协议 | 面对安全议题的停止自动服务、人工责任和本地资源协同。 | HOLD，需危机协议、责任主体与本地转介 Gate。 |

## 3. L0 首阶段候选：家庭支持评估入口

### 3.1 用户旅程

| 步骤 | 家长看见什么 | 家长做什么 | 平台上限 |
|---|---|---|---|
| 1. 说明 | “这不是诊断或给孩子打分；你可以跳过或随时退出。” | 知情选择是否继续 | 显示目的、最小数据、撤回/退出。 |
| 2. 当前关切 | “你现在最想一起理清什么？” | 自由文本或最小结构化选择 | 创建 Need，不解释原因。 |
| 3. 支持方向 | “你希望先获得哪类支持？” | 选择沟通、日常节奏、学习安排或暂不行动 | 创建 Intent，不设成长目标。 |
| 4. 选择边界 | “你可以先看已准入的文字支持，也可以暂不行动。” | 看候选、选择或退出 | 只显示现有 admission/T1 合格候选。 |
| 5. 家庭决定 | “下一步由你决定，可以暂停。” | ACCEPT / alternative / DISMISS + [] | 仅明确 Decision 后走 T2/Plan/Case。 |
| 6. 回看 | “这是本次服务过程，不是成长结论。” | 可选 FollowUp | 记录家庭主观感受，不写 outcome。 |

### 3.2 L0 的明确正清单

L0 仅可复用既有可信链：`Account → ACTIVE binding → ACTIVE membership → family scope → Need → Intent → admitted Resource → Family Decision → T2 → Plan/Case → FollowUp / Handoff`。它不增加测评分、儿童端、画像、报告、模型、通知、任务、积分、真人服务或商业能力。

### 3.3 L0 的明确负清单

| 禁止项 | 说明 |
|---|---|
| AI 诊断、综合分、雷达图、成长报告 | 自填需要不能升级为对儿童/家庭的客观结论。 |
| 工具量表原题、得分、cutoff | 未经独立工具许可、专业审阅和 Gate，不使用。 |
| 孩子端、游戏化、连续打卡、奖励 | 未成年人数据、操控和行为监测设计尚未获准。 |
| 专家/班主任/顾问转介 | handoff 只能安全留痕，不代表真人服务。 |
| 排行、分享、邀请、跨家庭比较 | 公开画像、跨家庭统计/推荐和传播继续 HOLD。 |
| 会员、订单、商城、拼团、积分 | 商业能力与支付/权益/履约继续 HOLD。 |

## 4. 成熟工具库：研究结论与未来准入条件

| 工具类别 | 例子 | 可以回答什么 | 不能回答什么 | 进入 Family 前的硬条件 |
|---|---|---|---|---|
| 家庭需要/共同决策 | 家庭需求访谈、Family-Centered Care Assessment | 家庭希望的支持、服务目标和参与感 | 儿童能力/风险/家庭好坏 | 目的限定、最小题目、退出和撤回；可不涉及第三方量表许可。 |
| 发展/社会情绪筛查 | ASQ-3、ASQ:SE-2 | 是否可能需要进一步了解/评估 | 诊断、预后、个体标签 | 正版许可、适龄/中文版、培训、计分/解释、私密讨论、转介网络。 |
| 家长压力 | PSI、PSS | 养育压力或支持需求的讨论入口 | 家长能力评级、家庭质量分、定价依据 | 工具许可、适配、危机路径、人工解释、禁止商业画像。 |
| 亲子互动观察 | NCAST-PCI、PICCOLO | 受训观察者可关注的互动支持点 | 自拍/视频/模型自动判断 | 受训人员、观察协议、监督与专业责任。 |
| 家庭安全/危机 | 安全清单、IPV/危机流程 | 是否需要优先安全处置或进一步了解 | 自动报警、自动转介、自动诊断 | 当地资源、人工责任、危机协议、隐私与安全设计。 |

成熟实践将筛查与综合评估区分开来：筛查通常短、快速，用于提示是否需要进一步了解；综合评估更全面，可能用于诊断或干预规划。筛查须有后续支持与转介协议。[1] ASQ 的公开指南强调，结果需要与家长共同审阅，结合文化、环境和家庭关切，且家长应参与后续选择。[2]

## 5. Consent、隐私与专业责任模型

| 控制项 | L0 当前候选要求 | L1–L3 未来附加要求 |
|---|---|---|
| 目的 | “帮助你说明当前希望获得的支持” | 工具名称、筛查目的、专业处理目的分别独立说明。 |
| Consent | SERVICE consent + 明确入口说明 + 可退出 | 评估/筛查专用 consent；接收方、保留期、再筛/转介逐项确认。 |
| 数据最小化 | Need/Intent/Decision/FollowUp 的最小事实 | 题目、原始回答、得分、解释、转介记录分层隔离。 |
| 可见性 | 当前家庭与授权角色 | 家庭、合格专业人员、组织之间需逐项 AccessGrant。 |
| 撤回 | 停止 Context Reuse，显示空投影 | 停止未发生的处理/转介；明确已被家庭保存内容的限制。 |
| 专业责任 | 无诊断/无转介，仅确定性路由 | 专业人员、主管、危机责任、当地资源和争议处理必须明确。 |
| 禁止二次使用 | 不训练、不画像、不跨家庭推荐、不公开、不商业排序 | 同样适用；不得因筛查结果提高价格、推送商品或激励分享。 |

## 6. 风险路由与 fail-closed 矩阵

| 事件 | 系统行为 | 禁止行为 |
|---|---|---|
| 无可信身份、disabled account、ambiguous context | `401/403`，不显示家庭内容 | 默认选人、复用旧会话。 |
| 无 consent / consent 已撤回 | 停止写入或空投影 | 保留可行动报告、推荐或画像。 |
| 家长不想回答 / 输入不足 | 提供跳过、退出、NO_ACTION | 逼答、自动补全、降低服务资格。 |
| 成熟工具未获许可/适配/培训 | 不呈现题目与评分 | 复制题目、改写题目、AI 解释分数。 |
| 结果临界/需进一步了解 | 非诊断文本、仅未来安全路径 | 病名、风险标签、自动转介。 |
| 安全/危机问题 | 停止自动支持，未来走人工协议 | 自动报警、向家庭成员/第三方外发。 |
| 跨家庭/公开/商业用途 | 拒绝 | 排名、营销、定价、拼团、分享。 |

## 7. 验证矩阵（若且仅若 L0 获独立实施授权）

| 层 | 最低验证 |
|---|---|
| 文案与无障碍 | “非诊断、可跳过、可退出、家庭决定”文本；纯文本和移动视口完整可用。 |
| 权限/Consent | Account、binding、membership、family scope、SERVICE consent、撤回与拒答。 |
| API | 只复用既有 Need/Intent/Decision/FollowUp；如需新契约须重新 Gate。 |
| 真实 PostgreSQL | 合成家庭正向链、跨家庭、disabled、ambiguous、撤回、幂等、NO_ACTION、资源降级。 |
| 安全/语义 | 零评分、零标签、零 outcome、零外部模型、零训练、零公开/商业路由。 |
| 浏览器 | 移动视口文本路径与浏览器后全量 API 回归。 |

## 8. Human Gate 裁决问题

1. 是否确认 Family App 的第一入口能力称为“家庭支持评估/家庭当下支持”，而不是“AI 成长诊断/家庭测评得分”？
2. 是否仅放行 L0 进入后续任务契约设计，并确认其零评分、零画像、零报告、零成熟工具题库？
3. 是否确认 L0 仅复用现有 Need/Intent/Decision/NO_ACTION/资源准入链；任何新增 DTO/API/DB 必须单独审批？
4. 是否确认 L1 任何工具使用都需版权、中文/文化适配、适龄、培训、人工解释、转介网络、危机协议与独立 consent Gate？
5. 是否确认 L2/L3 在真人服务、组织访问和专业责任体系未授权前保持 HOLD？
6. 是否确认所有测评相关数据禁止训练、画像、跨家庭推荐、公开分享、增长激励、会员分层、支付定价与商业触达？
7. 是否确认“进一步了解”只能显示非诊断文本与安全等待，不可自动转发或声称专业服务？
8. 是否确认 L0 获批后仍需独立 App 实现 Gate，且 PR #36 继续不 merge/master/pilot/production？
