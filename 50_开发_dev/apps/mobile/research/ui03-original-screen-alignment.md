# UI-03 原始成长解读画面对齐分析

## 对照依据

- 原始设计图：`research/baselines/ui03/core-03-ai-report.png`
- 当前运行态：从 UI-02 选择“亲子沟通”后进入 UI-03 的 Web 兼容入口
- 页面现状：`app/ui/UI-03.tsx`

## 原图可验证结构

| 区域 | 原图可见元素 | 原图可见功能 |
|---|---|---|
| 顶部栏 | 返回、`AI成长诊断`、更多、圆形功能图标 | 返回与附加操作入口。 |
| 家庭/孩子摘要 | 蓝色渐变卡、孩子头像、姓名、年龄、年级、测评来源与测评时间 | 说明当前解读的对象和测评上下文。 |
| 综合评估 | 五维雷达、五个维度数值、中心综合数值与等级、得分图例 | 展示多维评估结果。 |
| 核心问题 | 三个标签 | 概括当前关注主题。 |
| 成长建议 | 按 1、2、3 排序的三条建议 | 呈现优先级建议。 |
| 主行动 | `生成个性化方案` | 进入后续个性化成长方案。 |

## 当前运行态结构

| 区域 | 当前可见元素 | 已确认差异 |
|---|---|---|
| 顶部栏 | 返回、`家庭成长解读` | 缺少更多与圆形功能图标；标题不同。 |
| 输入摘要 | 家庭关注方向、家长观察边界 | 缺少孩子/家庭摘要卡与测评时间上下文。 |
| 内容主体 | Fact、Perspective、Hypothesis、Recommendation 四层卡片 | 缺少原图的五维图形、维度数值、核心问题标签与编号建议。 |
| 辅助说明 | 本机体验提示、解释方式、模型边界说明 | 原图未呈现这些工程/系统解释模块，占用了首屏内容空间。 |
| 行动出口 | 查看 90 天成长方案、查看阶段成长报告 | 原图为单一主行动“生成个性化方案”；UI-04 是当前可复用的对应目标页。 |

## 已确认需要修改的差异

1. **页面信息层级**：应恢复“对象/测评摘要 → 多维成长概览 → 核心关注点 → 排序建议 → 主行动”的原图顺序；当前以系统解释卡为主，不符合原图首屏结构。
2. **对象和测评上下文**：应增加只读的家庭/孩子摘要卡和测评时间来源；字段必须来自现有家庭上下文与测评投影，缺失时使用明确空态，不能编造个人信息。
3. **核心关注点与建议**：应将现有 Recommendation 转换为原图的关注标签和 1–3 条排序建议；保留 Fact/Perspective/Hypothesis/Recommendation 数据边界，但不必把内部分类标签作为首屏主要视觉。
4. **主行动**：应将主按钮改为“生成个性化成长方案”，映射到已存在的 UI-04；阶段报告可保留为次级入口。
5. **顶部操作**：需要从原始 Web 绑定取证“更多”和圆形图标的目标，未取证前不添加实际动作。

## 必须由用户确认的冲突

| 原图元素 | 与当前平台规则的冲突 | 需要确认 |
|---|---|---|
| `AI成长诊断` 标题 | 当前产品禁止儿童诊断，使用“家庭成长解读” | 是否仅复刻视觉结构并保留“家庭成长解读”标题。 |
| 中心 `72` 综合分与“良好” | 当前产品禁止家庭总分、儿童诊断与排名 | 是否以**无总分的五维成长概览**替代，或由用户明确批准特定评分口径。 |
| 预置孩子姓名、年龄、年级 | 当前不得编造家庭/儿童个人资料 | 是否在现有家庭上下文缺失时显示“等待家庭信息补充”的空态。 |

## 后续实施前提

在用户确认上述三项冲突的取舍之前，不修改 UI-03；确认后仅对已列出的结构、摘要、关注点、建议和 UI-04 主出口实施修复。
