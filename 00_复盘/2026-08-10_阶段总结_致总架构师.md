## 四、M1 Family Core 已形成的工程能力

### 1. Family 身份与成员

已可通过 API 与真实 PostgreSQL 完成:

- 创建 Family。
- 添加 Parent。
- 添加 Child。
- Child 的 `birth_date` 只作为事实保存,不会自动生成 LifeStage、GrowthProfile 或任何临床/成长标签。

### 2. Family Relationship

已完成 `CreateFamilyRelationship`:

- 支持 `PARENT_CHILD`、`GUARDIAN_CHILD`、`SPOUSE`、`SIBLING`、`OTHER`。
- `PARENT_CHILD` / `GUARDIAN_CHILD` 方向严格:guardian/parent -> child。
- `SPOUSE` / `SIBLING` 反向重复由 DB unique expression index 防护。
- 关系本身不会隐式创建 Consent、LifeStage、GrowthProfile 或 AI 权限。

### 3. LifeStage 显式赋值

已完成 `AssignLifeStage`:

- V1 只允许 `EARLY_ADOLESCENCE_12_15`。
- LifeStage 必须通过 Named Action 显式写入。
- `birth_date != AssignLifeStage` 已被测试锁定。
- Active assignment 支持版本化,旧 active row 会被关闭,新 row 成为 active。
- 不创建 Consent、GrowthProfile、Journey、Recommendation、Score 或 Ranking。

### 4. Consent 显式授权

已完成 `GrantConsent`:

- V1 subject 必须是 Child。
- Guardian 必须是同家庭 Parent,且存在 directed `PARENT_CHILD` 或 `GUARDIAN_CHILD` 关系。
- Actor 必须通过 M1 family manage permission,并且 `guardian.account_id === x-actor-id`。
- Consent 是 purpose-specific,不存在 `GENERAL` / `ALL` / `FULL` 同意。
- `SERVICE` 不等于 `MODEL_IMPROVEMENT`。
- `RESEARCH` 不等于 `CONTENT_PUBLICATION`。
- `policyVersion` 强制必填。
- 同 subject + purpose + 新 policy version 会保留历史:旧 active `GRANTED` 变为 `EXPIRED`,新 row 为 `GRANTED`。
- 新增 partial unique index `ux_consents_active_subject_purpose`,防并发重复 active consent。

## 六、对 Domain Spec 的遵守情况

本阶段严格遵守以下硬规则:

- `Perspective != Fact`。
- `Hypothesis != Fact`。
- `Recommendation != Decision != Action`。
- 核心状态必须走 Named Action。
- Relationship 不等于 Consent。
- Birth date 不等于 LifeStage。
- Consent 不等于 AI 执行、训练许可、研究执行或读权限。
- 不做 Family Total Score。
- 不做家庭 Ranking。
- 未成年人场景保留 Human Gate / Consent 边界。
- 未实现 World Model 或 Causal Episode 训练路径。

尤其是 TASK-105 与 TASK-106 已把两个容易混淆的边界用代码和测试锁住:

1. `birth_date` 只是 child fact,不会自动推断 LifeStage。
2. `PARENT_CHILD` / `GUARDIAN_CHILD` 关系只是资格边界,不会自动授予 Consent。

## 九、建议总架构师裁决

### 裁决 1:是否授权 TASK-107

建议授权 `TASK-107_FAMILY_CORE_INTEGRATION`,但限定为:

- 只实现完整 M1 flow integration 和 `GetFamilyAggregate`。
- 不实现 GrowthProfile、AI、Journey、Intervention、Recommendation、Score、Ranking。
- Aggregate 只能读取 canonical tables,不得做推断。
- 必须从 empty DB 完成:

```text
CreateFamily
-> AddParent
-> AddChild
-> CreateFamilyRelationship(PARENT_CHILD)
-> AssignLifeStage(EARLY_ADOLESCENCE_12_15)
-> GrantConsent(SERVICE)
-> GetFamilyAggregate
```

### 裁决 2:确认 M1 Aggregate 的响应边界

建议 TASK-107 aggregate 仅包含:

- family
- parents
- children
- relationships
- active LifeStage assignments
- active Consent summary by purpose
- audit/outbox/correlation 验证证据只进入测试与报告,不必暴露给普通 API response

明确不包含:

- GrowthProfile
- inferred LifeStage
- inferred Consent
- AI state
- Recommendation
- Score / Ranking

### 裁决 3:是否将 WithdrawConsent 插入 M1 或 M1.5

当前 GrantConsent 已能创建和版本化同意,但 withdrawal 尚未实现。建议:

- TASK-107 仍按原计划完成 Family Core Integration。
- TASK-107 后新增 `TASK-106B_WITHDRAW_CONSENT` 或放入 M1.5。
- Pilot 前必须完成 WithdrawConsent,否则 consent lifecycle 不闭环。

### 裁决 4:确认 M1 permission 技术债处理时点

当前 M1 permission 能支撑 Family Core,但不是最终权限模型。建议:

- TASK-107 不重构 IAM。
- M1 报告后开专门任务设计 durable actor/person/account/guardian role policy。
