### 7. 五层卡片与 spec Ontology 是同一件事的两次表达(**本次最重要的发现**)

`20_知识_knowledge` 的五层卡片,和 `10_规格_spec\02` 的 Knowledge/Intervention Ontology,是同一个模型被独立设计了两遍。字段几乎能对上:

| 五层卡片 | spec/02 对应物 | 对齐状况 |
|---|---|---|
| `Method.targets_constructs` | `Intervention.target_dimension` | 一致 |
| `Method.dose` | `Intervention.dose` | 一致 |
| `Method.contraindication` | `Intervention.contraindications` | 一致 |
| `Method.steps` | `Intervention.actions` | 一致 |
| `Method.grounded_in`(Theory) | `Intervention.mechanism` + `Evidence` | 一致 |
| `Card.evidence`(Grade E0–E7) | `Intervention.evidence_grade` | 一致,但 spec 未定义分级刻度 —— 代码里有 |
| `Construct` | `GrowthDimension`(24 维) | **部分**:Construct 有 `measured_by`/`proxy_risk`,24 维没有;spec 有四档状态(EMERGING/DEVELOPING/PRACTICING/STABILIZING),Construct 没有 |
| `Modality`(测量通道) | **spec 无此层** | **缺口** |

三个必须补的缺口:

1. **`Method` 缺 `risk_level` 与 `human_requirement`** —— 而 spec 的硬规则是"高风险家庭场景必须 Human Gate"。没有这两个字段,Gate 无从判定该不该触发。
2. **`Intervention` 缺 `failure_mode` 与 program 溯源** —— 五层卡片里有 `Method.failure_mode`(典型做坏方式)和 `derived_from`(源自哪个已验证 Program),这两条对交付质量很实用,spec 丢了。
3. **spec 没有 `Modality` 这一层** —— 而 `Modality` 强制校验 `privacy_risk` 与 `minors_handling`(缺失直接报 error)。spec 的 Consent/Safety 只到 Ontology 层,没落到"每个测量通道"的粒度。涉未成年人,这个粒度差别是实质的。

**未擅自改 spec** —— spec 是权威规格,改它应走变更评审。已记入 `10_规格_spec\ISSUES.md`。

### 8. spec 内部的五处冲突(已记录,未改)

读完 7 份文档后核出的自相矛盾,均记入 `10_规格_spec\ISSUES.md`:

1. **模型先于 Gateway 被使用**。硬规则要求"模型必须经 Model Gateway",但 Model Gateway 是 WBS `4.1`(W13–14),而 `2.6 GrowthProfile Engine`(W6–8)与 `3.3 Intervention Selection`(W9–10)的 Owner 都含 AI。若这两项用了 LLM,就在 Gateway 建成前违反了硬规则。
2. **DoD 在前三阶段不可能满足**。`06` 的 Definition of Done 要求"Golden Set 通过",但 Golden Set 是 `4.7`(W14–16)才建。Phase 2/3 的任何 story 都无法达标。需明确 DoD 分阶段生效。
3. **技术栈与既有代码不同语言**。`03` §17 推荐 NestJS/TypeScript,而仓库现有代码(五层卡片库)是 Python。跨语言边界未决。
4. **Outcome 的 baseline 没有来源**。迁移原则 3 禁止用历史打卡推导 Outcome,但全包没有规定 baseline 从哪来。`3.7 Outcome` 的验收标准要求"baseline/current/source 完整" —— 逻辑上 baseline 必须在 Journey 起点现测,而 WBS 里没有这项任务。**这是一个真实的任务缺口,不只是措辞问题。**
5. **FAMILY 域没有维度**。`02` §3.2 定义 `GrowthDomain` 有 4 个(CHILD/PARENT/RELATIONSHIP/**FAMILY**),但 24 个一期维度只覆盖前三个。FAMILY 域是空的。

### 9. spec 与 research 的接口张力(已记录)

`10_规格_spec\05` 的 Phase 5 直接安排"30→100 家庭 Pilot",商业阶梯(21天→90天→年会员)被当作既定前提。而这条阶梯正是 `25_研究_research` 的 BM 线要证伪的对象,当前 **0 条 supported**(一手运营数据为零)。

这不是文档错误,是真实的项目风险:**Pilot 的商业结论在 BM 线出裁决前无法解释**。建议把"BM 线出首次裁决"设为 G5 Pilot Gate 的前置条件。
