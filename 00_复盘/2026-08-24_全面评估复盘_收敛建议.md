# 2026-08-24 全面评估复盘：收敛建议

## 一句话结论

Family AI 当前不是“缺少资产”，而是资产、口径、页面、模型、后端和治理线同时展开，已经进入**范围膨胀大于可验证交付**的阶段。下一步不宜继续扩大 34 UI、模型、后台、工厂能力的并行开发，应收敛为一条可运营、可验证、可解释的 Family Core MVP 闭环。

建议当前阶段的核心目标改为：

```text
一个家庭
→ 完成一次家庭测评
→ 得到一份非诊断的成长解读
→ 明确确认一个支持方向
→ 生成/确认一个 90 天计划
→ 执行今日任务
→ 形成服务/资产/记录回看
```

商业、社区、名师、积分、会员、真实外呼、真实支付、公开分享、跨家庭比较、儿童直接作答、World Model 和生产级 Agent Runtime 暂时不进入主线交付。

## 当前真实状态判断

### 1. 最大问题不是技术能力不足，而是交付口径过宽

仓库里同时存在这些目标：

- 34 UI 逐页视觉复刻。
- 3 份 PPT 到产品能力的映射。
- 6 条业务闭环。
- Family Core / Growth OS。
- Model Gateway / Family Education Model / eval / harness。
- 商业权益、拼团、会员、积分、专家服务、社区、订单资产。
- 后端对象链、Named Action、Audit、Outbox、Consent、Human Gate。
- 开发工厂 / harness 自动化。

每一条都合理，但不能同时作为当前交付主线。继续并行推进会导致“页面看起来很多、测试文件很多、文档很多，但最终没有一条用户闭环能被稳定运营”。

### 2. 34 UI 应作为产品地图，不应作为当前 Sprint 的逐页实现压力

34 UI 的价值是：给产品范围、视觉语言、入口出口、风险边界提供地图。

但 34 UI 里至少包含以下需要 HOLD 或独立 Gate 的高风险面：

- 成长排行榜、同龄比较、家庭排名。
- 成长成果、效果承诺、家庭总分。
- 会员权益、积分兑换、真实订单、真实支付。
- 真人专家、真实预约、真实咨询履约。
- 公开社区、点赞评论、外部分享。
- 儿童直接作答或儿童侧智能体。

这些页面可以保留为只读、草稿、意向、家庭私有记录或沙箱投影，但不应为了“34 页完成”而补成真实业务能力。

### 3. UI-35 已经不应恢复，但 35 口径仍有残留

当前更合理的裁决是：

```text
UI-01..UI-34 = 唯一产品页面基线
UI-35 = 历史/附加基线，不作为产品页面、不作为路由、不作为验收对象
21 天挑战营 = Program / ProductOffering / Entitlement / GrowthAction / ServiceRecord 链路
21 天挑战营入口 = UI-01
商品详情 = UI-14
执行与记录 = UI-09 / UI-31 / UI-34
```

仓库里已有一些文件支持这个方向，例如 `FAMILY_CURRENT_TARGET_GAP_MATRIX_V1.md` 和 `FAMILY_35UI_RUNTIME_MATRIX_V1.json`。但 `CURRENT_SPRINT.md` 仍出现 `35_UI_BASELINE = KEEP`，`package.json` 中 `validate:34ui` 仍调用 `tools/validate-35ui-alignment.mjs`。脚本内部已检查 UI-01..UI-34 且禁止 UI-35，问题主要是命名和治理口径容易误导。

### 4. UI 实现已经有亮点，但“完成度”不能按文件数计算

近期已经做对的方向：

- UI-01 是首页，不是 21 天挑战营详情页。
- UI-14 承载 21 天挑战营商品详情。
- UI-04、UI-05、UI-14 已从“直接贴 PNG”转为组件化复刻。
- UI-14 不再把工程边界文案展示给家庭用户。
- UI-01 首页入口顺序已调整，`21天挑战营` 在 `90天成长计划` 前。

但不能因此宣称 34 UI 完成。当前更准确的说法是：

```text
路由/页面骨架：覆盖较广
视觉基线一致：只在少数页面经过重点修复
真实后端闭环：集中在少数关键动作
高风险页面：多数应保持 GATE_BOUNDARY
生产可运营闭环：仍需收敛验证
```

### 5. Model / harness / factory 应降级为工具，不应成为当前主产品线

Family Model、eval、harness、development factory 都是有价值资产。但在当前阶段，它们应服务于一条核心闭环：测评、解释、计划、行动、回看。

不建议现在继续把 factory 扩成“自动开发所有 UI 和前后端”的主线。原因是：

- 产品边界尚未收敛，自动化会放大错误口径。
- 34 UI 中高风险页面很多，不能靠生成补齐。
- 后端对象、Named Action、Human Gate、Model Gateway 还需要逐条验证。
- 如果没有稳定的验收定义，factory 只会制造更多半成品。

## 建议做减法：四类处理

### A. 保留并打磨为主线

只保留一条 Family Core MVP：

| 阶段 | 页面/能力 | 保留原因 |
|---|---|---|
| 首页入口 | UI-01 | 用户总入口，承载今日任务、测评、计划、服务入口 |
| 家庭测评 | UI-02 | 第一真实输入，必须受控、版本化、非诊断 |
| 成长解读 | UI-03 / UI-02-result | 将输入转成 Hypothesis / Recommendation，不写 Fact |
| 计划确认 | UI-04 | Recommendation 到 Decision 的关键桥 |
| 陪跑过程 | UI-05 / UI-09 | 将 Decision 变成可执行 Action 和回执 |
| 商业入口 | UI-13 / UI-14 | 只保留商品目录/详情/购买意向，不接支付 |
| 资产回看 | UI-31 / UI-32 / UI-34 | 用户能看到自己有什么、做过什么、服务记录是什么 |

这条线足够支撑“家庭成长平台”的第一版可运营闭环。

### B. 保留为只读/沙箱，不进入真实能力

以下页面保留视觉和入口，但只做只读、草稿、意向、沙箱或家庭私有记录：

- UI-15 邀请有礼：只保存邀请意向，不外发。
- UI-16 拼团/同行计划：只保存同行意向，不成团、不扣款。
- UI-18 会员中心：只读沙箱资产，不发放真实权益。
- UI-21/UI-23 服务/活动意向：只保存意向，不真人履约、不占座。
- UI-24/UI-32/UI-34 记录/资产：只读回看，不声称真实服务效果。

### C. 冻结，不纳入当前交付

这些应明确冻结，避免消耗主线注意力：

- 全量 34 UI 像素级逐页复刻。
- 社区公开发布、点赞、评论、推荐流。
- 成长榜单、跨家庭比较、家庭排名。
- 积分兑换、会员开通、真实订单、真实支付。
- 真人专家供给、真实咨询、外部通知。
- 儿童自主智能体、儿童直接诊断/作答。
- World Model、Causal Engine、强化学习。
- 开发工厂自动生成前后端的泛化能力。

### D. 删除或改名以减少误导

建议后续单独开一个“口径清理”小任务，不改业务，只做命名和文档收敛：

- `tools/validate-35ui-alignment.mjs` 改名为 `validate-34ui-alignment.mjs`。
- `CURRENT_SPRINT.md` 中 `35_UI_BASELINE = KEEP` 改为 `34_UI_BASELINE = KEEP; UI35_DELETED = YES`。
- `FAMILY_35UI_PROGRAM_*` 如果仍作为历史文件，应在文件头明确 `HISTORICAL` 或 `SUPERSEDED`。
- `todo.md` 中大量已完成的 35 UI 叙述应归档，不再作为当前执行事实。
- model docs 中 `UI-01..UI-35` 改为 `UI-01..UI-34 + historical UI-35 appendix` 或直接移除 UI-35。

## 建议的收敛路线

### 第 0 步：冻结扩张

立即停止以下动作：

- 不新增 UI 页面。
- 不新增数据库 schema，除非是当前 MVP 闭环的硬 blocker。
- 不新增真实外部模型默认调用。
- 不新增 factory target。
- 不继续追逐 34 UI 全量视觉修复。
- 不把商业/社区/名师/会员做成真实能力。

### 第 1 步：建立一个“当前唯一执行口径”

建议把当前执行口径写成：

```text
CURRENT_EXECUTION_MODE = FAMILY_CORE_MVP_CONSOLIDATION
UI_SCOPE = UI-01, UI-02, UI-03, UI-04, UI-05, UI-09, UI-13, UI-14, UI-31, UI-32, UI-34
UI35 = DELETED_FROM_PRODUCT_BASELINE
REAL_EXTERNAL_EFFECT = NO
REAL_PAYMENT = NO
REAL_HUMAN_SERVICE = NO
PUBLIC_COMMUNITY = NO
MODEL_SCOPE = INTERNAL_LOCAL_OR_MOCK_ONLY_THROUGH_GATEWAY
```

### 第 2 步：只打通一条端到端演示路径

推荐 2 周内只做这一条：

```text
UI-01 首页
→ UI-02 家庭测评
→ UI-03 成长解读
→ UI-04 90 天计划
→ UI-09 今日任务
→ UI-31 我的服务
→ UI-34 服务记录
```

UI-13/UI-14 作为“21 天挑战营商业入口”保留，但只到购买意向/服务资产，不进入支付。

### 第 3 步：每个页面只问四个问题

不要再按“页面是否存在”验收，改成四问：

1. 这个页面展示的状态来自哪里？
2. 用户能做的动作是不是 Named Action 或明确本地草稿？
3. 这个页面有没有把 Hypothesis / Recommendation 说成 Fact / Decision / Outcome？
4. 测试和浏览器证据是否覆盖这条路径？

四问答不上来，就不算完成。

### 第 4 步：建立最小验收门

MVP 收敛完成只需要这些证据：

- mobile `run check` 通过。
- contracts build 通过。
- MVP 路径相关 Vitest 通过。
- 8081 移动端浏览器能跑通关键页面导航。
- 无 UI-35 产品路由。
- 无真实支付、真实外发、真实专家、公开社区副作用。
- 文档口径不高于代码实况。

## 当前优先级建议

- 明确当前不是 35 UI，而是 34 UI + 21 天 Program。
- 把 `CURRENT_SPRINT.md`、验证脚本命名、model docs、todo 中最容易误导的 35 口径收束。
- 将历史 35 UI 文件保留但标为历史，避免反复恢复 UI-35。

### P1：完成 Family Core MVP 一条线

- UI-01 / UI-02 / UI-03 / UI-04 / UI-09 / UI-31 / UI-34。
- 重点不是新增页面，而是确认状态来源、动作边界和回执。

- UI-13/UI-14：商品目录/详情/购买意向。

### P3：延后 34 UI 全量视觉追平

- B 批：UI-13 至 UI-18。
- C 批：UI-19 至 UI-24。

## 风险清单

| 风险 | 当前表现 | 收敛处理 |
|---|---|---|
| 口径漂移 | 34/35 UI、M3/V4.1、MOS/Factory/Model 多口径并存 | 设一个当前执行真相文件，历史文件标注 superseded |
| 完成度误判 | 文件数、截图数、测试数被误认为业务完成 | 只按端到端路径和状态来源验收 |
| 假能力 | 支付、专家、社区、积分、成果等容易被 UI 文案包装成真实能力 | 一律沙箱/意向/只读/HOLD |
| AI 越界 | 模型输出可能被当诊断、事实或行动 | 继续强制 Model Gateway、Hypothesis 边界、家庭确认 |
| 工厂放大错误 | factory 在口径未稳时会复制半成品 | 暂停泛化，只服务 MVP 检查和回归 |
| 文档高于代码 | `PROJECT_STATUS`、todo、治理矩阵部分比当前代码更乐观或更旧 | 以后每次复盘以代码实况修文档 |

范围：

- model docs 中 UI-01..UI-35 的活跃口径

### 收敛任务 002：Family Core MVP Gate

目标：只验证一条主路径。

范围：

- UI-01 → UI-02 → UI-03 → UI-04 → UI-09 → UI-31 → UI-34
- API / contracts / mobile tests
- 8081 浏览器证据

验收：家庭可以从首页进入测评、看到非诊断解读、确认方向、进入计划、执行今日任务，并在服务/记录中回看。

### 收敛任务 003：21 天挑战营降级为 Program Slice

目标：避免 UI-35 回潮，也避免把 UI-14 做成完整课程后台。

- UI-01 入口

验收：不扣款、不真实开团、不外发、不恢复 UI-35；只形成受控意向和记录。

## 最终建议

现在最正确的动作不是继续“把 34 个 UI 都做得更像”，也不是继续扩 factory、模型或后台。最正确的动作是：

```text
冻结扩张
统一口径
保留 34 UI 为地图
删除 UI-35 的产品身份
只交付一条 Family Core MVP 闭环
把商业/社区/专家/会员/积分全部降级为沙箱或 HOLD
```

等这条闭环真的稳定，再把 34 UI 分批从“地图”推进为“可运营能力”。
