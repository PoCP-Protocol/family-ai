# 03｜资料归档与命名规范

本规范用于后续新增资料的归档、命名、引用和升级路径。

核心原则：

> 原始材料只保存，不直接当结论；结构化资料要标明来源、状态和用途；进入规格或研究前必须经过判断。

---

## 一、目录职责

| 目录 | 应放内容 | 不应放内容 |
|---|---|---|
| `30_素材_materials/` | 原始 PPT、图片、访谈录音转写、会议纪要原文、客户材料 | 二次加工后的结论、实施规格 |
| `30_素材_materials/_extracted/` | 从原始材料抽取出的文本、页码、OCR、可再生中间文本 | 人工改写后的观点 |
| `10_规格_spec/` | 经过评审冻结的产品、Ontology、技术、WBS、门禁规格 | 未评审的想法、临时脑暴 |
| `25_研究_research/` | 假设、证据、研究议题、裁决报告 | 没有证据等级的宣传判断 |
| `20_知识_knowledge/library/` | 理论、构念、方法、实践、测量卡片 | 原始 PPT 整页内容 |
| `40_产出_derived/` | 汇报版、结构化整理、复盘报告、阶段性派生产物 | 唯一来源材料 |
| `90_归档_archive/` | 非本项目材料、历史中间产物、可再生但不常用文件 | 当前项目权威文档 |

---

## 二、资料命名规则

建议统一使用：

```text
YYYYMMDD_资料类型_主题_版本_状态.扩展名
```

示例：

```text
20260809_访谈纪要_家长续费原因_v0.1_raw.md
20260809_研究证据_亲子沟通干预_v0.1_review.md
20260809_规格草案_OutcomeV1_v0.2_draft.md
20260809_复盘报告_Foundation阶段_v1.0_final.md
```

### 资料类型建议

| 类型 | 用途 |
|---|---|
| `原始素材` | PPT、图片、录音、合同、原始表格 |
| `抽取文本` | OCR、逐页文本、语音转写 |
| `访谈纪要` | 用户、顾问、助教、专家访谈 |
| `会议纪要` | 决策会、评审会、复盘会 |
| `研究证据` | 外部论文、报告、监管、运营数据分析 |
| `规格草案` | 未冻结的产品/技术/Ontology草案 |
| `规格正式` | 已冻结规格 |
| `复盘报告` | 阶段性总结 |
| `决策记录` | ADR/Decision Log |

### 状态建议

| 状态 | 含义 |
|---|---|
| `raw` | 原始材料，未加工 |
| `extract` | 抽取文本，未解释 |
| `draft` | 草案，可修改 |
| `review` | 待评审 |
| `final` | 已确认版本 |
| `deprecated` | 已废弃，仅留档 |

## 三、资料元数据模板

新增任何非原始资料，建议文件开头包含以下元数据：

```yaml
---
title: 资料标题
created_at: 2026-08-09
version: v0.1
status: draft
owner: 待定
source:
  - path: 30_素材_materials/_extracted/逐页文本_含页码/02_战略白皮书30页.txt
    pages: [6, 12, 18]
claim_status: strategic_judgment
review_required: true
related_spec:
  - 10_规格_spec/01_Family总体产品架构.md
  - 10_规格_spec/02_Family业务架构与Ontology.md
---
```

`claim_status` 建议取值：

| 值 | 含义 |
|---|---|
| `raw_source` | 原始来源 |
| `summary` | 摘要或整理 |
| `strategic_judgment` | 战略判断 |
| `hypothesis` | 待验证假设 |
| `supported` | 已有足够证据支持 |
| `falsified` | 已被证伪 |
| `decision` | 已决策 |
| `spec` | 已进入规格 |

## 四、从资料到规格的升级路径

任何材料不能直接从 PPT 进入开发，应经过以下路径：

```text
原始材料
→ 逐页抽取 / 会议纪要
→ 主题归类
→ 主张识别
→ 状态标注：事实 / 判断 / 假设 / 冲突 / 红线
→ 证据或决策补充
→ 规格草案
→ Gate 评审
→ 规格正式版
→ 开发任务
```

### 可以进入规格的条件

至少满足以下条件之一：

1. 已由业务 Owner 明确决策，并记录为 Decision。
2. 已有足够证据支持，并在研究模块中可追溯。
3. 属于安全、合规或伦理红线，必须直接纳入门禁。
4. 属于实施架构边界，例如 Build vs Buy、Model Gateway、OntologyAdapter。

### 不应进入规格的内容

- 百亿/千亿估值等融资叙事；
- 未验证的转化率、续费率、裂变率；
- 未经证据支持的“有效”“显著改善”；
- 临床化诊断或疗效承诺；
- 以家庭排名、总分、攀比为基础的增长机制；
- 未明确 Consent 的数据使用设想。

## 五、从资料到研究的升级路径

凡是出现以下表达，都应进入 `25_研究_research/` 或 `20_知识_knowledge/byresearch/`：

- “证明……成立”
- “用户一定会……”
- “转化率可达到……”
- “能形成护城河”
- “显著改善……”
- “降低投流依赖”
- “AI 能提高……”
- “可复制到其他赛道”
- “家庭成长数据具有资本价值”

研究化流程：

```text
主张
→ 可证伪假设
→ 反例条件
→ 所需证据等级
→ 证据收集
→ 裁决：supported / falsified / undecided
→ 回写规格或战略材料
```

示例：

```text
主张：21天挑战能带来第一次可见小改变。
假设：完成至少14天行动的家庭，在第21天 Relationship/Parent 某维度 Outcome 指标上出现可观察改善。
反例：完成率高但 Outcome 无变化；或变化只来自自我报告且无行为证据。
所需证据：Pilot 一手数据 E5 + 结构化 Outcome。
```

## 六、材料引用规范

引用资料时，必须尽量包含：

1. 来源文件路径；
2. 页码或章节；
3. 原始表述或概括；
4. 当前状态；
5. 是否已进入规格或研究。

推荐写法：

```text
来源：30_素材_materials/_extracted/逐页文本_含页码/02_战略白皮书30页.txt，第18页。
原始主张：真正的护城河是家庭成长数据库。
当前状态：待验证假设。
处理方式：进入 DATA-01，需用 Pilot 数据验证画像完整度与交付/留存关系。
```

不推荐写法：

```text
资料里说家庭成长数据库就是护城河，所以我们直接做数据中台。
```

## 七、决策记录规范

凡是会影响产品方向、数据结构、AI 权限、商业模式、安全边界的判断，都应记录为 Decision Log。

建议格式：

```markdown
# Decision YYYY-MM-DD-编号｜标题

## 背景

## 选项

## 决策

## 理由

## 影响范围

## 风险与补救

## 关联资料
```

必须记录的决策包括：

- 首发 LifeStage；
- 第一条 Vertical Slice 的问题切口；
- 21 天挑战与 90 天 Journey 的关系；
- 成长报告的定位；
- 年度会员的核心价值；
- 首批 AI Agent 顺序；
- Human Gate 风险分类；
- 历史数据迁移边界；
- 哪些能力 Build，哪些 Buy/Integrate。

## 九、最低执行纪律

1. 原始材料不覆盖、不改写。
2. 派生材料必须写来源。
3. 战略判断不能伪装成事实。
4. 商业假设必须进入研究或 Pilot。
5. 安全红线直接进入门禁。
6. 开发需求必须从规格来，不能从 PPT 直接来。
7. AI 相关资料必须说明 Model Gateway、Eval、Human Gate 和 Outcome。
8. 未成年人数据资料必须说明 Consent、Purpose、Lineage 和最小化原则。

---

## 十、一句话规则

任何新增资料都要回答：它来自哪里、属于哪一类、当前能证明什么、不能证明什么、下一步应进入规格、研究、决策还是归档。
